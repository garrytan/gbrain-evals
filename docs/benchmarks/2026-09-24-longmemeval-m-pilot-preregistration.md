LongMemEval is a public test of answering questions from dated conversation histories. This pilot uses its actual cleaned medium history, not the easier oracle history containing only evidence sessions. The [official source](https://github.com/xiaowu0162/LongMemEval) identifies six question types, session-level evidence IDs and a separate abstention marker. The [cleaned dataset card](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned) says noisy sessions were removed from the original release. We do not remove anything else.

## Frozen measurements and comparison

The retrieval comparison uses the existing `gbrain-hybrid` scoring formula at top five, balanced mode with reranking and autocut explicitly off, and no query expansion or session-diversity over-fetch. It requests five native chunks. The native `recall_all@5` numerator is the number of answerable questions for which **all** required original session IDs appear among those five returned chunks, normalized by case and unique in first-result order. A complete pilot cell has a denominator of 24 answerable selected questions, with no infrastructure exclusion or successful-subset fallback; an attempted system-under-test query error is a miss, while a guard/dependency/provenance error leaves the cell incomplete. Native `recall_any@5` and `ndcg_any@5` are secondary and must not be reported as all-required recall. The four `_abs` cases are outside the native recall denominator and retain the existing separately labeled diagnostic. Do not average abstention into the 24 or call source-session recall exact original-passage coverage.

Keep every actual returned indexed chunk in order, with its chunk ID, text hash, source ID, occurrence, date and original source hash. The v2 indexed projection records whether the chunk text matches one unique literal source span, only whitespace-reflow text, nonliteral text or an ambiguous span; offsets are null when no unique literal span exists. If any returned chunk lacks that span, the entire case marks strict raw grounding unavailable, but still counts its session ID in native recall. Foreign, altered or expanded evidence is a hard error. Evidence coverage and answer accuracy are distinct from session recall. A separate answer run would use frozen returned excerpts only, the fixed approved OpenRouter Sonnet 4.6 generator and the official LongMemEval answer-accuracy evaluator for the official QA metric. The existing `longmemeval-answers.ts` judge is a **secondary grounding check**, not the official scorer; it requires its own separately approved answer/judge budget. Do not infer answer accuracy from retrieval or relabel grounding as official accuracy. No answer/judge calls are admitted by this preregistration.

**Evidence alignment limit discovered before scoring:** A keyless pass over all 59,762 candidate-equivalent chunks found 54,769 uniquely literal spans in the rendered original sessions, 3,423 that matched only after whitespace collapse, 1,524 that did not match even then and 46 with multiple identical literal positions. These are indexed chunk texts, not question or answer content. The existing v1 secondary grounding evidence requires one exact original source slice per returned chunk and cannot honestly certify the latter 4,993 chunks. The earlier strict all-chunk offset build stopped on a selected history; that failed artifact remains separate. The subsequent **v2 indexed-projection** build freezes every real indexed chunk ID, normalized text/hash, chunk source and source occurrence/hash before query, with a typed raw alignment and null offsets unless a unique literal span exists. It retains all five actual results for native session recall; if any returned chunk lacks a unique literal span, it marks that entire case's strict raw grounding unavailable. It neither drops those chunks from retrieval scoring nor feeds this new capture to the unchanged v1 answer/grounding loader. There is still no pilot quality result or admitted answer phase.

## Source-only construction boundary

The build process may read only one sanitized source file at a time. It imports every session occurrence in published array order with its original date into a fresh per-question index and completes construction before a separate query process receives the question and score labels. Freeze the source index snapshot and every indexed chunk ID/text/hash first, and record separate snapshot and manifest hashes before opening the query artifact. Source occurrence keys make otherwise colliding page slugs unique, but scoring maps them back to the original upstream session ID. A returned indexed chunk is accepted only if its ID, source occurrence and text match that frozen index; unknown or changed chunks and generated cue text are hard errors. Unique literal raw offsets are an additional grounding status, not a prerequisite for native session recall. The full selected original JSON is for the query/scorer process only. The default runner still holds question and answer labels while importing, so running its unchanged import loop on this pilot would violate the source-only boundary.
