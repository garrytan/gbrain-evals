# BrainBench v1: finding people through their relationships

**Historical run: April 18, 2026.** Branch `garrytan/link-timeline-extract`, PR #188; in-memory PGLite. The original run took about 3 minutes without API keys or network access. These are the measurements from that run, not a score for the current release. See the [retrieval refresh](2026-09-09-retrieval-refresh.md) for current results.

A note can mention a company without saying that its author works there. Keyword search finds the mention. A typed relationship records what the mention means: employee, founder, investor, or advisor. This experiment asked whether using those relationships first helped gbrain find the right people.

The combined graph-first search and text fallback returned more correct answers in its first five results:

| Metric              | BEFORE PR #188 | AFTER PR #188 | Δ            |
|---------------------|----------------|---------------|--------------|
| **Precision@5**     | 39.2%          | **44.7%**     | **+5.4 pts** |
| **Recall@5**        | 83.1%          | **94.6%**     | **+11.5 pts**|
| Correct in top-5    | 217            | 247           | **+30**      |

Current Precision@5 asks how many of the first five result slots are relevant. Recall@5 asks how much required evidence those results contain. These historical figures predate the metric audit: older code could reward short lists and count duplicate hits, and the original per-query receipts are unavailable. The 44.7% / 94.6% numbers therefore cannot be treated as verified scores under today's corrected formulas.

## What we tested

The corpus contains 240 fictional pages generated by Claude Opus 4.7: 80 people (40 founders, 20 partners, 10 engineers, 10 advisors), 80 companies (60 startups, 15 venture firms, 5 acquirers), 50 meetings (15 demo days, 25 one-to-ones, 10 board meetings), and 30 concepts. Generation cost about $15 once; the saved pages are in `eval/data/world-v1/`.

The prose uses six ways to describe founders and eight to describe investors, roughly 1–2% word-level typos, several writing styles, and timelines from 2021–2026. References include Markdown links and bare page identifiers. This makes the text less uniform than a template, but it remains synthetic data.

The report describes 196 relationship questions: 60 about attendance, 60 about employment, 45 about investment, and 31 about advice. The earlier configuration was v0.10.0 without automatic links, database extraction, or path traversal. The later configuration combined v0.10.3 and v0.10.4: query typed relationships first, then fill missing results with text matches.

## Why result order mattered

For “Who works at Acme?”, a text match may return investors, advisors, and other companies. A `works_at` edge narrows the result to the requested relationship. The historical top-five comparison was:

| Metric              | BEFORE | AFTER  | Δ             |
|---------------------|--------|--------|---------------|
| **Precision@5**     | 39.2%  | 44.7%  | **+5.4 pts**  |
| **Recall@5**        | 83.1%  | 94.6%  | **+11.5 pts** |
| Correct in top-5    | 217    | 247    | **+30**       |

Looking at the entire returned set tells a different story. Here “set” ignores order, and F1 combines precision and recall:

| Metric              | BEFORE (grep) | AFTER (vector-grep-rrf-fusion) | Graph-only (ablation) |
|---------------------|---------------|----------------|------------------------|
| **F1 score**        | 57.8%         | 57.8%          | **86.6%**              |
| Set precision       | 40.8%         | 40.8%          | **81.0%**              |
| Set recall          | 98.9%         | 98.9%          | 93.1%                  |
| Total returned      | 632           | 632            | 300 (-53%)             |
| Correct returned    | 258           | 258            | 243                    |

The combined system returned the same 632 items as the text fallback, including 258 correct ones. Its improvement was ordering. The graph-only experiment returned 300 items, 243 correct, with 86.6% F1 versus 57.8% for the text set. That is useful evidence for relationship questions, with a recall cost: 93.1% versus 98.9%. It does not establish that graph search is better for every kind of question.

The historical table calls its combined column `vector-grep-rrf-fusion`; read it according to this experiment's graph-first-plus-text method, not as the later adapter with that name. These older labels do not identify one interchangeable implementation across reports.

| Link type   | Expected | Graph found / returned | Recall | Precision |
|-------------|----------|------------------------|--------|-----------|
| attended    | 134      | 131 / 134              | 97.8%  | 97.8%     |
| works_at    | 50       | 50 / 79                | 100.0% | 63.3%     |
| invested_in | 60       | 50 / 56                | 83.3%  | 89.3%     |
| advises     | 17       | 12 / 31                | 70.6%  | 38.7%     |

Attendance was easier than advice. The graph found 97.8% of expected attendance links with 97.8% precision, while the advisor result had only 38.7% precision. A relationship is only as reliable as the extraction that created it.

## Bugs the experiment exposed

- Code examples containing page-like strings were being turned into links. Blanking fenced and inline code before matching reduced the measured code-fence leak rate to 0%.
- Timeline writes accepted a year such as 99999. The fix required a real `YYYY-MM-DD` date, a year from 1900–2199, and a round-trip date check that rejects February 30.
- Investment prose such as “led the Series A” was missed by rules looking for “invested in.” All 60 detected investment links initially had the wrong type. Broader phrases, a 240-character context window instead of 80, more careful advisor rules, a person-role prior, and investment-before-advisor matching moved overall type accuracy from 70.7% to 88.5%, and investment accuracy from 0% to 91.7%.
- “Founder of” was missed by a rule that recognized only “founded.” Adding noun forms and treating founder links as acceptable answers to this fixture's employment questions moved graph recall from 53.8% to 93.1%. That employment rule is a benchmark convention, not a claim that every founder remains an employee.

## Other checks in this run

Identity resolution tested 100 entities with eight alias forms each. An alias is another way of naming the same entity, such as a full name, initials, handle, or email address. The historical implementation found aliases written in the page much more often than aliases it had to infer:

| Alias category | Recall (top-10) |
|----------------|-----------------|
| Documented (in canonical body)     | 100.0% |
| Undocumented (initials, typos)     | 31.0%  |

The 50-entity timeline fixture contained 10–20 dated events per entity over five years:

| Sub-category    | Recall | Precision |
|-----------------|--------|-----------|
| Point           | 100%   | 100%      |
| Range           | 100%   | 100%      |
| Recency (top-3) | 100%   | —         |
| As-of           | 100%   | —         |

Those timeline results used the structured `timeline_entries` table. “As of” answers were assembled by filtering and sorting in the harness; they did not demonstrate a native `getStateAtTime` operation.

Latency below is from synthetic stores of 1,000 and 10,000 pages. P50 is the median; P95 is the time below which 95% of calls finished. Graph traversal, unlike simple page reads, was not sub-millisecond:

| Op                 | 1K P50  | 1K P95  | 10K P50 | 10K P95  |
|--------------------|---------|---------|---------|----------|
| get_page           | 0.08ms  | 0.12ms  | 0.08ms  | 0.15ms   |
| search_keyword     | 0.19ms  | 0.52ms  | 0.20ms  | 0.59ms   |
| traverse_paths d=2 | 10.1ms  | 12.6ms  | 91.4ms  | 176.4ms  |
| putPage_single     | 0.12ms  | 0.20ms  | 0.12ms  | 0.42ms   |

At 10,000 pages, bulk import reached 5,848 pages/second and link writes reached 8,752/second. P95 keyword search stayed below the historical 200ms threshold.

The robustness set covered 22 hand-written edge cases and reported 133 operation attempts: 133 succeeded, with no reported crashes or silent corruption. Inputs included 100,000-character pages, several writing systems, code fences, false substring matches, invalid dates, and nested Markdown. The operation-contract suite reported 50/50 checks passing across validation, local/remote access rules, parameterized queries, and resource limits; its original design described 30 operations with five input variants.

## Reproducing the historical experiment

Run these commands against the corresponding historical gbrain checkout. Today's aggregate runner has more categories and different requirements.

```bash
bun run eval/runner/all.ts
```

Regenerating the corpus was an optional, approximately $15 step:

```bash
bun eval/generators/gen.ts --max 240 --concurrency 6
```

The original report deferred source-attribution tests (estimated $200–300 of corpus generation), prose-link tests at 5,000+ pages, agent skill tests (estimated $2,000), end-to-end workflows (estimated $1,000), and licensed multimodal datasets. These were April planning estimates, not current run prices.

Queries were generated from the fictional world's facts, and both configurations received the same corpus. The missing graph relationships included names mentioned without explicit links. The report proposed entity recognition as a follow-up for that 5.8-point set-recall gap. Reproducibility within a seeded fixture is useful; it does not measure variation across real users' notes.
