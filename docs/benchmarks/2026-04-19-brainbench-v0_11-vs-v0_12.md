# Better extraction gave the graph more useful facts

**Historical comparison: April 19, 2026.** On the same 240-page corpus and 145 questions, the recorded gbrain precision rose from **22.1% to 49.1%**, and recall from **54.6% to 97.9%**. This compared two gbrain versions, rather than treating the difference between unrelated adapters as a graph-only effect.

These results predate the August 31 metric and corpus corrections. Preserve them as a record of the experiment, not current scores or an exact estimate of one feature's contribution. See the [retrieval refresh](2026-09-09-retrieval-refresh.md).

## The two versions

| Slot            | SHA       | Dated        | Version label |
|-----------------|-----------|--------------|----------------|
| BEFORE          | `d861336` | 2026-04-18   | v0.11.1 (Minions + canonical migration) |
| AFTER (HEAD)    | `b81373d` | 2026-04-19   | v0.12.1 base + eval harness Phase 3    |

The old source tree was placed in a separate worktree at `d861336`. Both versions received the same evaluation code, pages, questions, and ranking logic. Because v0.11 lacked `traversePaths`, its adapter used `getLinks` or `getBacklinks` with the same relationship-type and direction filters.

That compatibility change matches the intended one-edge queries. It would not be equivalent for a traversal of two or more edges. Both versions ran five times, and both received the fix for the runner's erroneous exit code 99.

Current Precision@5 divides relevant results by five slots; current Recall@5 measures required evidence found there. The historical table below predates the short-list and duplicate-hit metric corrections noted above and lacks the original per-query receipts needed for a corrected recount.

| Adapter (config)        | BEFORE v0.11.1 | AFTER v0.12.1 | Δ             |
|-------------------------|----------------|----------------|---------------|
| **gbrain — P@5**  | 22.1%          | **49.1%**      | **+27.0 pts** |
| **gbrain — R@5**  | 54.6%          | **97.9%**      | **+43.3 pts** |
| Correct in top-5 (run 1)| 99 / 261       | **248 / 261**  | **+149**      |

Both versions reported zero variation under shuffled ingestion order. The hybrid reference stayed at 17.8% precision and 65.1% recall. It shared gbrain code, but the report found no change to its hybrid search, chunking, or embeddings across these versions. The separate grep and vector baselines did not use the changed source tree.

## What extraction changed

A graph cannot answer an investment question if “led the Series A” was saved only as an untyped mention. This release recognized more of those relationships, across more pages:

| What got extracted       | v0.11.1     | v0.12.1     | Δ          |
|--------------------------|-------------|-------------|------------|
| Pages with extractable links | 124 / 240  | 240 / 240   | +116 pages |
| Typed links created      | 136         | 499         | **×3.7**   |
| Timeline entries created | 27          | 2,208       | **×82**    |

The changes included broader rules for investment, employment, founding, and advice; a context window increased from 80 to 240 characters; link extraction on page writes; and timeline extraction for database-ingested pages. Before that last change, much of the timeline logic ran only during filesystem sync.

The earlier adapter comparison had a 31.4-point precision gap between gbrain and the hybrid reference. Here the older gbrain version was only 4.3 points ahead of the reference, and the newer version added 27.0 points. That supports the importance of extraction quality. It does not separately measure the value of extraction, graph storage, and graph query logic: several changes landed together, and the relationship parser matched the fixture's query templates.

## Reproduction

The historical procedure is retained below. It needs the compatibility patch described in the original session commit message; the command block alone is not a complete fresh-machine recipe.

```sh
# From providence/, current HEAD (b81373d)
bun run eval:run --adapter=gbrain
#   gbrain N=5: P@5 49.1% ±0, R@5 97.9% ±0

# Historical side
git worktree add -f ../gbrain-eval-v0.11 d861336
cp -r eval ../gbrain-eval-v0.11/
ln -s $PWD/node_modules ../gbrain-eval-v0.11/node_modules
# Patch: gbrain uses getLinks/getBacklinks instead of traversePaths
#        (v0.11 doesn't have traversePaths). Same direction + linkType filter
#        semantics, different primitive. See the perl one-liner in the
#        session commit message for the exact diff.
cd ../gbrain-eval-v0.11
bun eval/runner/multi-adapter.ts --adapter=gbrain
#   gbrain N=5: P@5 22.1% ±0, R@5 54.6% ±0
```

The old extractor reported usable links on 124/240 pages; the newer one on 240/240. That log count is distinct from query accuracy. More extracted data is helpful only when it is correct and searchable.

This experiment did not measure the extra write latency of automatic extraction or the 2,208 timeline writes versus 27. Nor did it test sync, publishing, linting, integrations, or other v0.12 work. Its fictional biographies use a limited vocabulary. Real notes and paraphrased questions remain necessary tests.
