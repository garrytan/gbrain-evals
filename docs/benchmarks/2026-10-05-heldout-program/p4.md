# P4: core memory tier and save before compaction

This page mirrors the evaluation records of gbrain [#6015](https://github.com/garrytan/gbrain/pull/6015) for the [nine-plan held-out program](../2026-10-05-heldout-program.md). The growth-aware save notice passes its sealed pressure gate: +11.4 judged points on BEAM-500K, and it stays on. The always-loaded core memory tier fails its sealed core gate on `gpt-6.1-sol` and defaults off.

| Idea | Setting | Held-out verdict | Default |
|---|---|---|---|
| Growth-aware save notice before compaction, and `remember` with `items` | `memory.pressure.enabled` | **PASS** (pressure gate, BEAM-500K sealed) | on |
| Always-loaded core memory tier | `memory.core.enabled` | **FAIL** (core gate: `gpt-6.1-sol` −2.4 points) | off |

## Preregistration

[`CORE_MEMORY_PREREGISTRATION.md`](https://github.com/garrytan/gbrain/blob/815d7806dc750206665e9e7737f46b5ee4fe9ab0/docs/eval/CORE_MEMORY_PREREGISTRATION.md) at the PR head fixes the arms, metrics and pass bars before any sealed cell:

- **Harness.** gbrain-evals `eval/runner/p4-stream/` streams a conversation into an agent with a 32k-token window through gbrain's real Claude Code hooks and forces compaction. Arm A′ is master. Arm B gets the growth-aware save notice and batched `remember`. Arm C loads a question-blind standing-preferences page as core memory every session. Every arm gets the same page.
- **Pressure gate.** BEAM-500K sealed, 24 conversations, 480 questions, `claude-sonnet-5-5`. The notice stays on if B − A′ is at least +3.0 accuracy points with the cluster-bootstrap lower bound above 0, and no question type's interval lies entirely below −2.0. A report-only slice runs the first 4 conversations on `claude-opus-5-5`, `gpt-6.1-sol` and `claude-fable-5-1`.
- **Core gate.** BEAM-100K sealed, 14 conversations, 56 preference-following and instruction-following questions, all four models. Core stays on if C − A′ is at least 0 on every model not at ceiling, and neither category's interval lies entirely below −2.0.
- **Cost.** Cost gates neither default. Cost per question and per correct answer are reported with the verdict. The eval cap is $2,500, development included.

## Development (sets no default)

Record: [streaming dev pilot](https://github.com/garrytan/gbrain/blob/815d7806dc750206665e9e7737f46b5ee4fe9ab0/docs/eval/decisions/p4-stream-dev-pilot/README.md).

- **Invalid early results.** Every early B result ran with two faults: batched `remember` refused items that carried their own provenance, and the harness's 700-token reply cap cut batched tool calls to empty arguments. Both are fixed: per-item provenance in gbrain, and a tool call cut off at the reply cap is reissued with an 8,192-token cap and counted (gbrain-evals `8cfae29`). The LongMemEval-S B numbers, including a +50.0-point growth-trigger result, were measured with both faults and are not evidence for or against the feature.
- **BEAM-500K, corrected harness and build** (one development conversation, `claude-sonnet-5-5`, judge `gpt-4.1-mini` 10×). B scored 58.0% against A′'s 46.8%: +11.2 points, question-bootstrap 95% CI [−2.8, +27.0]. B costs $0.73 against $0.45 per question, and $1.26 against $0.97 per correct answer. A′ scored 60.7% on the same conversation in an earlier run, so one conversation moves about ±14 points between runs.
- **BEAM-100K core check** (one development conversation). C scored 54.4% against A′'s 35.7%, and answered all four preference and instruction questions against A′'s two and a half. Two questions per category only show that the arm runs as intended.
- **LongMemEval-S cannot move core.** The profile page comes from the first session, which is gold evidence in only 11 of 500 questions.
- **Spend.** Development spend is about $310 from the budget ledger.

## Held-out verdicts

| Decision | Material | Result | Verdict |
|---|---|---|---|
| Pressure gate ([file](../2026-10-05-heldout-verdicts/p4-pressure-heldout-2026-10-05.json)) | BEAM-500K sealed, `claude-sonnet-5-5`, A′ (master `8c9a8e9a4`) vs B (#6015 `66956a3ee`, pressure notice on); 460 paired questions in 23 conversations | 51.7% → 63.0%, +11.4 points [+8.3, +14.4]; no question type's interval lies entirely below −2.0 (summarization −1.4 [−9.5, +7.4], instruction following −0.7 [−7.2, +5.9]); largest gains on temporal reasoning +24.3, knowledge update +20.7 and multi-session reasoning +20.1; cost $0.68 → $0.87 per question, $1.32 → $1.38 per correct answer | **PASS** |
| Core gate | BEAM-100K sealed, 14 conversations, 56 preference and instruction questions, A′ vs C | `gpt-6.1-sol` −2.4 points [−5.4, +0.3], below the C − A′ ≥ 0 bar; `claude-sonnet-5-5` +4.6 [−0.4, +10.7]; `claude-opus-5-5` +3.4 and `claude-fable-5-1` +2.3 on partial runs still finishing | **FAIL** (custodian report; file pending) |
| Pressure report-only slice | first 4 BEAM-500K sealed conversations, three more models | not run yet | pending |

**Pressure gate details.** One conversation (`500k-11`) is excluded: its B arm stopped at the $280 shard cap before running, so its 20 A′ rows have no pair. B issued 1,342 save notices over 1,647 compactions and left 309 compaction segments without a notice (A′: 1,278 of 1,278). Evidence-saved rate rose from 39.6% to 60.7%.

**Caveat on BEAM session dates.** The pressure gate ran on the memory-qa BEAM loader before its date fix (gbrain-evals `evals/beam-session-dates`). That loader dated only the first turn group of each BEAM batch, so the streaming harness headed most sessions `[Conversation on an unknown date]`. Both arms saw exactly the same headers, so the paired B − A′ verdict stands. Facts saved before compaction often had no date, though, so the per-type breakdowns for temporal reasoning and event ordering are affected and should not be read as measurements of dated conversations. The core gate's preference-following and instruction-following questions do not depend on dates.
