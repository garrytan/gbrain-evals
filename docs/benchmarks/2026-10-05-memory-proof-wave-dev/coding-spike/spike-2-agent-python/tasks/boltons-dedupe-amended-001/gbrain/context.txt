Git commit: Fix OrderedMultiDict equality to compare values against plain mappings
OrderedMultiDict.__eq__ has a branch for comparing against a non-OMD
mapping (anything with a keys() method, e.g. a dict). That branch
computes other[selfk] == self[selfk] but throws the result away, so it
only checks that every key of self exists in other and never compares
the values. As a result an OMD compares equal to any same-keyed mapping
regardless of the values:

    >>> omd = OMD([('a', 1), ('b', 2)])
    >>> omd == {'a': 999, 'b': 2}
    True   # should be False

The existing test_eq doesn't catch this because its dict case is written
as d == omd, which dispatches to dict.__eq__ rather than OMD.__eq__; the
buggy branch is only reached with the OMD on the left.

Compare the values and return False on mismatch. The same __eq__ is
duplicated in urlutils.OrderedMultiDict (used by QueryParamDict), so it's
fixed there too. Added regression tests for both.
