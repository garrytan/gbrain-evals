# Counted entity-dedupe data

Each completed run has a cell record, its page groups and its scores. The out-of-the-box run that failed has a cell record only. The records keep the world fingerprints, build or configuration, status and attempt timing. Memory-system receipts use the system IDs and version numbers from the [comparison bundles](../../../comparison-systems.md), and `subjects.json` contains only the unmapped page keys needed for rescoring. The groups themselves are unchanged. Matcher summaries keep aggregate token counts and verdict counts, not per-call logs. The two choice records contain the held-out results that selected the memory-system settings.

The tuned Splink output lists clusters at its lower review threshold, not individual edges. Its `direct-edges.json` and the corresponding default file come from a keyless replay of the frozen adapters on the same counted world. The replay matched the original prediction counts and reproduced every recorded cluster at every recorded threshold. These files contain only the designed pairs that survived the prediction cutoff, with their scores; all-pair counts are in `settings.json`. Other classic adapters did not export the candidate pairs behind their clusters.

The memory-system samples list the same seeded sample of 50 pages per run. An audit checked that each sampled page title matches the rendered input and that mapped nodes name that page among their sources. That is a check of the readout, not independent proof that the original entity merge was right. The notes in [the report](../../2026-11-18-entity-dedupe-h2h.md#memory-systems) flag questionable assignments.
