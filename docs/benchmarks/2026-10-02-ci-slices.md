# N1 and N5 now gate every pull request through CI-sized slices

**Update, 2026-10-03.** At gbrain `48ed5e8` both slices pass every rule again (N1-ci 64/64 and 57/57 in 59 s, N5-ci 0 prohibited outputs and 120/120 in 80 s). See the [October 3 rerun](2026-10-03-wave7-repin.md).

**Finding.** Two of gbrain's lifecycle contracts now block regressions in CI. N1 checks that an updated value replaces the old one without losing its history. N5 checks that a forgotten fact stays out of every active recall surface. Each runs as a small slice of its full category, on PGLite, without a key, in about a minute. Both slices passed every preregistered rule on their first run at gbrain `d44296c` (v0.60.30.0) on October 2, 2026.

[gbrain](https://github.com/garrytan/gbrain) is a memory system for agents. It stores notes as Markdown and builds a database index for search and relationships. The slices drive real gbrain processes: the gbrain CLI serving MCP over stdio, plus `gbrain call` for the trusted local caller.

## What each slice checks

A concrete N1 case: a fictional person's city changes four times through a Facts table, and the last change reverts to an earlier city. After every round, a restart, a full reimport of the notes folder and a round of concurrent writes, the current city must come back as current, each older city must stay readable as history, and a private value must never reach a remote caller.

A concrete N5 case: an agent remembers "Hazel Example keeps bees" (fictional), forgets it, then the notes folder is restored from before the forget and re-synced. The claim must stay out of recall, search, query, the entity card, `context_pack` and the active Facts rows at every checkpoint, while the same sentence on another person stays active.

| Slice | Subset of the seeded ledger | Cell | Checkpoints |
|---|---|---|---|
| `knowledge-update-ci` (N1-ci) | 4 of 9 entities, every chain on them unchanged | PGLite, stdio MCP, trusted reads through `gbrain call` | updated, restart, reimport, concurrent |
| `forget-residue-ci` (N5-ci) | 13 of 24 canaries (the ones on 2 of 4 entities) | PGLite, stdio MCP, private canaries through `gbrain call` | witness, immediate, settled, stale reimport, restart, concurrent |

The [preregistration](2026-10-02-ci-slices-preregistration.md) froze the subsets, the cell and the rules in commit `5adb955`, before either slice ran. Each slice keeps every safety contract and utility floor of its full category and adds signal floors computed from the sliced ledger, so a slice cannot pass by measuring nothing.

## Why stdio MCP and not the CLI transport

The request was a PGLite CLI slice. The CLI transport starts a new process for every read, and a bare `gbrain call get_stats` takes about 1.0 s on this machine, about 0.7 s of it opening the PGLite data directory. The full N5 CLI cell made 508 calls and took 575 s. A CLI cell under two minutes would keep roughly 90 calls, too few for the checkpoints and tiers that make the contracts meaningful.

The stdio cell is still the gbrain CLI (`gbrain serve`) running as its own process. Every trusted read and every private write and read in the slice still goes through `gbrain call`, so both process boundaries stay in CI. It is also where the October 1 run found the N5 hot-memory residue bug, which a CLI cell cannot see.

## What the slices leave out

The CLI and HTTP transports, Postgres, and parts of each ledger stay in the full runs only. N1-ci omits the distinct-source ontology revert and the appended trajectory. N5-ci omits the prose canary, the private retained canary, the concurrent same-text twin, and the read-only and foreign-source forget attempts. Run the full categories before a release or a re-pin:

```bash
bun eval/runner/n1-knowledge-update.ts --engines pglite,postgres
bun eval/runner/n5-forget-residue.ts --engines pglite,postgres
```

## Reproduce

From the repository root, with Bun 1.4.0 or newer and no keys:

```bash
bun install
bun eval/runner/n1-knowledge-update.ts --slice ci --output /tmp/n1-ci
bun eval/runner/n5-forget-residue.ts --slice ci --output /tmp/n5-ci
BRAINBENCH_ALLOW_SKIP=1 bun run eval:brainbench   # the CI step, slices included
```
