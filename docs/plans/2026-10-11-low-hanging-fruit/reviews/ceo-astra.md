Do not approve the wave with these shipping rules. It treats smaller responses and cheaper extraction as improvements before establishing which information can safely disappear, and its proposed experiments cannot support several of its release decisions. ## F1 — The objective rewards cheaper failures without protecting against confidently wrong answers

The plan's success rule, “not lower beyond the … 95% interval,” never specifies a non-inferiority margin or which interval bound must pass. If it means that a loss must not be statistically significant, an underpowered experiment becomes easier to pass. Twenty task clusters do not become forty independent tasks because two models answer them. Item 2 also quietly changes the headline objective from dollars per successful task to dollars per task, which can improve when an agent does less work and fails more often.

The existing evidence makes this a product-risk decision, not statistical housekeeping. The confirmation report records 22 confidently wrong gbrain answers versus 14 for files on M, and 16 versus 2 on S; H4 on M is already down 15 points with an interval excluding zero (`gbrain-evals/docs/benchmarks/2026-10-10-model-ladder-hard-confirmation.md:43-47`). Pooling these outcomes with harmless timeouts conceals the failure users are least likely to detect. The report also identifies H4 as conflicting sources, distinct from H3's look-alike accounts (`:18`), so the deferred alias-label fix is not an established diagnosis.

Add an explicit wrong-answer guardrail, report failures by kind and family, and use cost per successful task consistently. Preregister a tolerable success loss and require the paired lower bound to exceed its negative margin; an interval that permits larger harm is inconclusive, not a pass. If the budget cannot resolve that rule, keep behavioral candidates experimental rather than promoting them by absence of significance. This does not require solving H4 in this wave; it requires not making it worse unnoticed.

## F2 — Item 2 proposes deleting evidence, not merely repeated instructions

The two trailers are not static. `searchCountLine` emits this call's keyword count, count failures, displayed range, omitted-evidence count, and the exact next-page arguments (`gbrain/src/core/search/keyword-paging.ts:205-226`). `dateLabelLine` computes its explanation from the date-source kinds actually present in this response (`gbrain/src/core/search/date-labels.ts:24-40`). MCP deliberately appends both on every applicable call (`gbrain/src/mcp/dispatch.ts:402-407`).

Deduplicating these by session can hide the second search's continuation or make a fallback import date look like a document date after an earlier response taught a different date interpretation. A character-count replay will count that information loss as a win. It also contradicts item 3's premise that a result's limitations must accompany the affected call.

Remove whole-trailer suppression from item 2. If repetition is worth optimizing, separate genuinely invariant coaching from per-call counts, continuations, unavailable-count warnings and date provenance. Keep the latter visible every time and add a two-call regression where the counts and date-source kinds change. The plan itself says notices are only about 2% of characters; that saving does not justify weakening completeness and temporal interpretation.

## F3 — The budget is not priced against the workload, and Opus is not optional

The proposed 150-cell round assumes $0.08 per cell. The committed M receipts instead total $58.7782 for 100 Sonnet gbrain cells, $28.1223 for 100 Sol cells, and $86.8920 for 100 Opus cells, excluding the judge. That is approximately $0.59, $0.28 and $0.87 per cell. The published success counts and dollars per success independently imply the same rates (`gbrain-evals/docs/benchmarks/2026-10-10-model-ladder-hard-confirmation.md:25-29,53-62`; raw source: its `main-cells/results.jsonl`). A 150-cell round evenly split across those models projects to about $86.90 before slot construction and judges, not $13. This is a historical projection, not a claim that every selected future task costs the same; the plan provides no cheaper task mix that supports its estimate.

Nor can the wave solve this by omitting Opus when money runs out. The repository requires the newest Opus, GPT and Sonnet in counted agent-task comparisons (`gbrain-evals/CLAUDE.md:87-103`). The default recommendation explicitly changes Opus installations, making that omission substantively important as well.

Reprice the complete paired matrix from identified receipts, include all three required families from the start, and reserve construction, judging and final-tree confirmation within the same $100 cap. Reduce the number of behavioral hypotheses or defer one paid candidate before reducing model coverage. A budget ledger prevents overspend; it does not make an incomplete experiment decision-worthy. Budget exhaustion must remain an incomplete verdict under the coordinator contract.

## F4 — Item 1's savings story does not describe the shipped entry points

Changing `tokenmax` to `balanced` does not remove one model call per `search`. The search operation explicitly passes `expansion: false` (`gbrain/src/core/ops/search.ts:756-775`). Conversely, `query` requests expansion by default and explicitly forwards that choice, irrespective of the bundle (`:868,975-990`). The cited LongMemEval comparison used direct retrieval harnesses, fixed top-5 results and replayed expansion variants (`gbrain-evals/docs/benchmarks/2026-10-04-longmemeval-opaque-followups.md:30-37,43-52`); it is not a measurement of the proposed init change through the current MCP search path.

The automatic per-chunk write-cost claim is also too broad. The current import-mode resolver explicitly demotes `per_chunk_synopsis` to `title` (`gbrain/src/core/import-contextual-mode.ts:21-37`), and the import path describes synopsis generation as a separate backfill rather than an inline call per chunk (`gbrain/src/core/import-file.ts:606-621`). Paid backfill savings and ordinary write savings cannot be counted as the same thing.

Reframe item 1 around its real treatments: result limits, evidence budgets, rerank-pool size and any separately exercised enrichment lifecycle. Require receipts of resolved settings and provider calls through fresh-init `search`, `query` and a representative write before claiming those savings. Distinguish that onboarding experiment from changing a restored existing brain's read-time configuration: the Cat 40 runner applies config overrides after restoring an already-built snapshot (`gbrain-evals/eval/runner/cat40/gbrain-arm.ts:428-449`). Keep existing brains untouched, but do not attribute new-install or ingest effects to a read-time toggle experiment.

## F5 — “Rerun the facts gate” neither isolates reasoning nor bounds the behavior change

The old gate compares extraction models, not Haiku reasoning on versus off. It prepares one product build and runs every arm on it (`gbrain-evals/eval/runner/facts-absorb-gate.ts:318-322,342-354`). Applying the proposed unconditional option to that build changes the controls too. Its default-model validator still expects Sonnet 4.6 (`:48,235-240`), while current gbrain's measured default is Haiku 5.5 (`gbrain/src/core/facts/extract.ts:55-90`). An unchanged rerun therefore cannot supply the claimed before/after reasoning result.

The risk is larger than this one default. The extractor honors explicit extraction, tier and global model choices (`gbrain/src/core/facts/extract.ts:72-90`); an unconditional `thinking: 'off'` reaches those users too. The gateway intentionally replaces configured reasoning options, and its effect varies by provider (`gbrain/src/core/ai/thinking-off.ts:31-44,112-148`). A Haiku-only gate does not authorize silently overriding a user's deliberately configured higher-reasoning extractor.

The quality budget is already partly spent: Haiku lost 4.6 points of natural-transcript coverage in the previous switch (`gbrain-evals/docs/benchmarks/2026-10-08-facts-extraction-model.md:90-98`). The reused natural-prose rule permits a ten-point point-estimate loss, not demonstrated non-inferiority (`gbrain-evals/eval/runner/facts-absorb/natural.ts:25-39`). Reapplying that tolerance to successive cost cuts can compound losses.

Scope the default change to the measured Haiku/default-resolution case unless wider provider behavior is separately approved and tested. Amend the preregistration before spending: compare the same current Haiku configuration on identical corpora with only reasoning policy changed, pin the amended scorer, validate every attempt including retries, and set an explicit incremental quality allowance with the cumulative loss reported. Report actual reasoning savings; the cited $0.62 is the cost of all output tokens, including useful extracted facts, not a measured removable reasoning bill.

## F6 — Selective reverts invalidate a gate measured only on the combined wave

The sequencing runs paid rounds on a head containing several simultaneous changes, then removes whichever items appear to fail. It does not define item 2's exact control or require confirmation after those reverts. An improvement from smaller mode limits can mask harm from removing row information; removing the mode change later leaves a different product from the one measured. A green CI/tree receipt satisfies code-validation requirements, not the behavioral comparison.

Define each comparison as one controlled difference, sharing controls where valid to save money. Record the exact settings, corpus snapshot and product trees for each arm, then verify the final retained combination against its specified baseline. Reserve that confirmation in the budget before running exploratory cells. Cat 40 already enforces complete, consistent experiment grids (`gbrain-evals/eval/runner/cat40/records.ts:178-197`); give the release decision the same discipline rather than attaching a bundled-head result to an unmeasured selectively reverted tree.

## F7 — “Same output on generated names” is too narrow for an identity-resolution rewrite

Item 5 treats alias/title lookup as a replaceable implementation detail. It is a user-visible identity decision. Today's resolver considers aliases, raw and normalized slugs, exact titles and suffix matches, filters private/deleted pages, then applies entity-type and recency tie-breaks (`gbrain/src/core/verbs/entity-card.ts:210-303`). A fast path can return a plausible but different page without ever triggering its miss-only fallback. Testing the generator's names will not necessarily exercise those collisions, source boundaries or visibility states.

Make the scope “reuse the existing resolution semantics without assembling unused card sections,” not “create another alias/title resolver and compare one synthetic world.” Add adversarial parity cases for colliding aliases/titles, explicit namespaced slugs, duplicate slugs across sources, private/deleted candidates and identity siblings on both engines. This is the minimum evidence for byte-identical behavior; otherwise the speedup risks accelerating the confident identity mistakes already visible in Hard.

## F8 — Item 6 commits to an optimization before its instrumentation can reject it

The plan admits that the 1.4-second search median is not attributed, then makes synthetic 120-ms embedding delay the shipping gate. That demonstrates overlap under an invented delay, not a material reduction in agent-visible time. The named baseline uses 400 synthetic pages and deterministic providers (`gbrain/docs/designs/refactor-wave-1/perf-baseline.md:19-25,53-64`), while the target is a 55,000-document workload. Current query-embedding cache hits can also remove the provider latency entirely (`gbrain/src/core/ai/gateway.ts:1818-1833`).

Keep stage timing first and make parallelization conditional on observed cold/warm critical-path contribution. Collect those timings during the already-budgeted task rounds rather than adding a new paid study. If the gain is negligible, defer the scheduling change even if the synthetic benchmark passes. If it proceeds, require no new provider calls on opted-out/keyword-only requests and preserved degradation behavior; today's provider and modality checks occur after the lexical work (`gbrain/src/core/search/hybrid.ts:1101-1142`). An earlier call is not automatically the same operation merely scheduled faster.
