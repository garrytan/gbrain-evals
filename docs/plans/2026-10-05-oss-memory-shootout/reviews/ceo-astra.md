# CEO outside-voice review: OSS memory shootout

## 1. Verdict

Keep the six requested systems, but do not approve the counted run under this plan yet. The proposed comparison mixes retrieved evidence, reconstructed full sessions, and native agent runtimes, while its cost and custody gates do not yet establish that the promised experiment can run. Fix the measurement contracts and resolve the exact run matrix first, then publish workload-specific results rather than a universal memory-system ranking.

Reviewed the draft dated 2026-10-05 at `docs/plans/2026-10-05-oss-memory-shootout/PLAN.md`; references to `PLAN.md` below mean that file. Short runner paths are relative to `eval/runner/`; bare `run.ts` and `corpus.ts` refer to its `memory-qa/` directory. Short benchmark report names are relative to `docs/benchmarks/`, and `coverage-and-categories.md` is the supplied September 28 audit. This is a strategy and scope review, not an implementation review or a runtime certification. No repository files were changed and no other reviewer's output was read.

## 2. Findings

1. **Critical | How each run stays fair; Architecture | The existing QA path gives gbrain evidence that other arms may not receive.** `memory-qa/run.ts:362-375` searches chunks, converts them to session IDs, then reconstructs entire sessions from the evaluator's original corpus. An adapter returning extract-first or memory-bank facts is not equivalent to that path. graph-pipeline's `recall()` can even return an already generated answer unless `only_context=True` is set [U3]. Giving an external reader that answer measures two answerers, not the promised fixed reader. **Fix:** prescribe the primary lane as “the fixed reader receives only evidence returned through the tested product's public read API, with no answer-generation endpoint and no evaluator-side source expansion.” If a full-session expansion lane is retained for historical parity, apply exactly the same expansion to every eligible product and label it separately. Persist the exact ordered reader context. Define whether the 8,000-token cap covers evidence or the entire input, count with the reader's tokenizer, and specify deterministic packing: the current `approxTokens` uses characters divided by four, and `packSessions` stops at the first oversized session (`memory-qa/qa.ts:39-60`). Neither proves an equal token budget.

2. **Critical | Architecture, `ingestSession(namespace, session)` | Passing the existing session object to vendor metadata can reintroduce answer leakage.** `Session.id` is not safe product input: LongMemEval's loader preserves the original haystack IDs (`memory-qa/corpus.ts:212-227`), while the current runner substitutes `occurrenceId` only at import (`run.ts:319-325`). The repository already withdrew an answer score because gold sessions had `answer_` IDs (`docs/comparison-systems.md:82`). memory-bank explicitly includes metadata in the extraction prompt [U6], so “metadata only” is not a safe boundary. **Fix:** put a sanitizer before every adapter. Expose only opaque source and namespace IDs, dated text and speaker roles; never pass raw dataset IDs, answer labels, category, gold status or `_abs` markers. Keep the reverse map exclusively with the evaluator. Add a captured-request contract check covering HTTP bodies, MCP responses, prompts, filenames and metadata, not just the rendered note text.

3. **High | P1 sealed set; Phases 3 and 4 | The plan promises unopened evidence without identifying or reserving it, and Phase 3 crosses existing custody boundaries.** The runner allows only `dev` and custodian `sealed` splits; LoCoMo has three dev conversations and seven sealed, and BEAM-100K has six dev and fourteen sealed (`memory-qa/run.ts:130-137,215-223`; `docs/decisions.md:75-85`). “All 10” and “20 conversations” cannot be ordinary Phase 3 development runs. Separately, `--benchmark custody` accepts any supplied corpus and hashes what it reads; it does not by itself establish the published sealed-confirmation commitment or remaining opening allowance (`corpus.ts:282-305`). That set's policy permits at most three release decisions and prohibits using its results to select settings (`docs/benchmarks/2026-09-29-sealed-confirmation-protocol.md:102-109`). **Fix:** name the exact corpus commitment, permitted use and available opening allocation in preregistration; have the custodian verify current access history without exposing rows. Keep Phase 0 and harness work on dev only; have the custodian execute existing sealed portions and any fresh confirmation corpus after every adapter/configuration is frozen. Replace “the only fully fair cell” and “nobody has seen” with “a confirmation set held back from adapter development, subject to the recorded access history.” Blindness does not eliminate generator or workload bias.

4. **High | Systems table; agent-runtime fallback; generic MCP arm | Several rows name different products or execution contracts as though they were interchangeable.** extract-first's pinned README says its published headline scores measure managed-platform proprietary optimizations, not OSS [U1]. OpenMemory's current README says it is being sunset [U2]; “yes (OpenMemory)” is not proof that Cat 40 exercises the pinned extract-first SDK. temporal-graph explicitly distinguishes itself from managed Zep [U4]. agent-runtime's App Server owns agent execution over WebSockets, whereas Cat 40's `Arm` supplies tools to the repository's own loop (`cat40/loop.ts:23-35`; [U5]). A whole agent-runtime agent is not a drop-in MCP memory arm. **Fix:** freeze engine, server wrapper and deployment identity independently. Label temporal-graph OSS and extract-first OSS explicitly, with no claim to reproduce Zep or managed extract-first. Require the extract-first MCP wrapper's resolved SDK/version/configuration to match the QA arm, or report a distinct configuration. Implement a agent-runtime local-backend capability spike, not a presumed archival API. If only the native agent path exists, keep agent-runtime in a separately labeled native-runtime result using the same tasks, not the controlled-tool-loop ranking. This retains the requested system without pretending the reader and loop are matched.

5. **High | Fairness rules 2 and 3; Risks | “Vendor default” is undefined, and “matched isolates memory design” is too strong.** temporal-graph 0.30.2 defaults to `gpt-5.5` plus `gpt-4.1-nano`; extract-first 2.2.1 uses `gpt-5-mini`; graph-pipeline 1.6.2 can choose local GLiNER extraction when no key is present, or LLM extraction when one is supplied. markdown-notes 0.23.2 uses local FastEmbed by default [U1, U3, U4, U7]. Supplying the runner's credentials can silently change the installed default. Matching one extraction model does not match temporal-graph's small-model calls, rerankers, prompts, query planning or consolidation. **Fix:** replace the prose default with a per-product resolved manifest: install command/extras, documented recipe, every model role, dimensions, graph setting, search recipe, optional reranking, background jobs, and readiness condition. Use the documented local/self-hosted recipe, not a substituted service called “default.” Rename the other arm “common extraction/embedder configuration” and say it controls those two inputs only. Do not downgrade optional components silently when a dependency or provider is absent.

6. **High | Fairness rule 3; Phase 6 | The new reader experiment conflicts with the repository's model policy, and Cat 40 has a forbidden hidden default.** `CLAUDE.md:84-97` requires current Opus, GPT, Sonnet and Fable for answer-model benchmarks; one GPT LoCoMo cell is not that matrix. The compatibility plan uses several old readers, not the single historical link allowed by the rule. More concretely, `cat40-model-ladder.ts:410` defaults its claims judge to `gpt-5.4-mini`, which the house rules explicitly ban running. **Fix:** preregister the current four-family reader matrix on frozen retrieval, with an explicit single historical bridge if needed. Keep the fixed judge as a measurement instrument, not an accidental reader comparison. Set a permitted Cat 40 claims judge explicitly or `none` when no claims metric is published. Price the actual matrix before approving spend. Vendor-internal old models must be clearly separated from the models the harness chooses for its comparison.

7. **High | Phases and gates; $1,200 cap | The cost gate measures the wrong pilot and the shared cap is not yet enforceable.** Phase 0 specifies one LoCoMo conversation, but the risk row says that phase measures a LongMemEval haystack. Those are different ingestion workloads. `docs/decisions.md:66-73` estimates about $1 per LME-S question per arm for gbrain's fact-extraction lane alone. At temporal-graph's pinned default and the ledger's $5/M input price, 100 histories of 115K tokens imply $57.50 for one raw-text pass before extraction output, additional graph calls or query work (`budget-ledger.ts:1033`). Six competitors × 50 tasks × five models is 1,500 Cat 40 cells; if both configurations apply there, it is 3,000 before repeats or slot construction. The existing $0.238 gbrain cost is not a rival estimate, but it demonstrates why the distinction matters. Finally, the existing proxy recognizes only three provider routes and charges an unrecognized request zero (`cat40/gbrain-arm.ts:33,90,100-123`); remote Python containers do not inherit Bun's fetch guard. **Fix:** enumerate every cell, including gbrain versions, reader variants, retrieval budgets, repeats and ingestion reuse. Pilot one dev LME haystack, one BEAM history and one Cat 40 slot as well as LoCoMo. Require fail-closed metering for every paid route, reserve from one parent allowance or partitioned allowances whose sum cannot exceed the cap, and include VM-hours, storage, local-model warmup and retries. Do not interpret a budgeting stop as a product failure. Keep $1,200 as a ceiling, not a claim that the current matrix fits it.

8. **High | Phase 1 parity; Phase 6 historical reuse; Report | The gbrain control changes identity in three places, and Cat 40 is already known to be at the ceiling.** The plan names `739e5cc` and “current master,” asks exact starting-line reproduction, and reuses October 4 Cat 40 cells. The QA starting line is actually `6622a119e` (`2026-10-05-heldout-program.md:19`), while the latest published Cat 40 row is `51f865d78`, with two repeats and its third use of that world (`2026-10-02-model-ladder.md:9-25,44-50`). That report says the 50 tasks cannot separate frontier memory systems on success. **Fix:** use `6622a119e` only for a frozen replay-based refactor parity check, then freeze one exact current gbrain SHA for the shootout. Require deterministic retrieval/context parity, not exact fresh stochastic QA scores. Reuse historical Cat 40 cells only when world, task, model, prompt, tool surface, configuration, repeat selection and scorer hashes match; otherwise rerun or label them historical. Keep Cat 40 as integration, cost and safety evidence, but preregister that ceiling ties do not establish equal capability. Replacing it with a harder category is a separate User Challenge, not an automatic change.

9. **High | Cat 40 finance-text leaks and write-back | A common MCP transport does not create a common authorization or mutation contract.** Gbrain's arm deliberately invokes untrusted remote reads so private pages are hidden (`cat40/gbrain-arm.ts:2-13`). Several listed systems offer namespaces rather than document-level permissions. Handing finance notes to them and scoring a leak tests an unimplemented application policy, while filtering them outside the product tests the filter. Existing unsafe-write detection only recognizes arguments named `path`, `slug`, `id`, `old_path` or `new_path` (`cat40/arms.ts:209-217`), so a new vendor's `memory_id` or `document_id` can escape the check. **Fix:** retain all families but publish a capability matrix: native enforcement, caller-enforced isolation, or unsupported. Run the caller-enforced control separately from native-policy claims and include the existing `fs-acl` control in interpretation. Register each adapter's mutation and source-ID mappings, verify protected state after the call, and restore all async/derived state before the next task. “No leak observed” must not become “privacy guaranteed.”

10. **High | Provenance rule; `MemorySystem.retrieve`; PMB | A source label is not yet a valid ranked evidence set.** A merged fact or entity may cite several episodes. graph-pipeline's docs expose source IDs on chunks or reference-bearing context, while the broad `source="graph"` tag is not a session ID [U3]. Putting each session in its own isolated dataset merely to obtain a source label may prevent cross-session graph reasoning. PMB is stricter still: the existing adapter maps results to exact fixture beliefs and supports scope and exclusions (`eval/precisionmembench/gbrainAdapter.ts:76-86,135-147`); its structural cases are supplied by the shared harness, not the product (`:4-11`). The proposed interface only promises context and sources. **Fix:** keep one namespace per conversation and attach per-session source identity inside it. Return ranked evidence items with their exact text and one-to-many source references; specify a deterministic source-ranking rule and label it source-session coverage, not proof the needed fact survived extraction. For PMB, preserve the upstream adapter contract and scorer, support belief-level provenance/scope/exclusions, and mark the cell unmeasurable when the public API cannot map outputs faithfully. Never resolve a vague generated fact to a gold belief using the answer key. Report product-dependent PMB cases separately from harness-computed structural passes.

11. **High | Failures published; paired intervals | The proposed reporting language is stronger than the runner's current denominator accounting.** `memory-qa/run.ts:412-435` excludes failed retrieval rows and computes QA only over numeric scores. Its resume path retries error rows, but the final aggregation reads every appended row (`:231-238,402-418`), so a recovered error can remain beside its replacement. A table can list errors yet still rank survivors unfairly. LoCoMo also has only ten independent conversations, not nearly two thousand independent trials; the decision kit labels its seven-conversation sealed split diagnostic (`docs/decisions.md:80`). **Fix:** preregister expected IDs, one scored terminal outcome per ID, separate attempt history, and fixed-denominator service-quality scores alongside completed-call quality. Product failures are misses for service quality; invalid harness, billing and provider setup conditions are labeled invalid/blocked, not a product loss. Cluster QA intervals by conversation and agent results by task, keep repeats within clusters, declare primary contrasts, and correct multiple superiority claims. Treat the 100-question category-balanced LME subset as its own sampled estimand, not a vendor's 500-question score (`run.ts:165-182`).

12. **High | P3 update and forget | An absent answer does not prove that memory was forgotten, and `update(fact)` can hand systems the solution.** A reader can abstain while the old fact remains retrievable. Deleting an entire namespace would pass a forgotten-canary check but destroy retained utility. The existing audit specifies residue across derived tiers, reimport resistance and retained-canary controls (`coverage-and-categories.md:352-357`), none of which is in the portable plan's gate. **Fix:** define three observable contracts before building the category: append a dated correction through normal ingestion, explicitly delete a known source through the public API, and test post-delete retrieval/answers. Keep direct CRUD replacement separate from automatic correction resolution. Include paraphrases, duplicate sources, completed background consolidation, restart, documented reimport behavior and unrelated retained facts, with no-op and delete-everything negative controls. Report API-observable non-retrievability only; storage erasure, backups and compliance are out of scope unless independently verified.

13. **Medium | The question; architecture and reuse | The premise that only incompatible vendor numbers exist is false, and the plan does not evaluate existing neutral-harness work.** AMB already has fixed modes for retrieval, RAG, agentic RAG and native agents, plus memory-bank, graph-pipeline and hybrid-search rows [U8]. The repository audit already recommends investigating that route (`coverage-and-categories.md:232,256`). This is not a reason to replace gbrain-evals: custody, session scoring, existing receipts and Cat 40 are useful local advantages. **Fix:** replace the opening with “We lack a matched, reproducible comparison of these six OSS releases against gbrain.” Add a Phase 0 reuse check of AMB's public adapter contracts and licenses, and reuse any suitable implementation rather than rebuilding six ingestion clients from descriptions. Cite AMB as related evidence, with its own configuration limits, not as proof of an independent or exhaustive ranking.

14. **Medium | P1 LoCoMo; published claims | The plan treats the current answer key and judge as adequate without addressing a known validity concern.** The prior audit explicitly flags LoCoMo label and judge problems (`coverage-and-categories.md:217,257`), while the current loader directly uses upstream answers (`memory-qa/corpus.ts:198-206`). A large matched run can measure a shared grading defect very precisely. **Fix:** preregister a blinded answer-key/judge audit on development examples and report original-key results unchanged. Any corrected-key sensitivity analysis needs its own frozen revision before counted evaluation; do not silently repair labels after seeing which system loses. Keep category 5 abstention and trap repetition distinct, as the current scorer already permits (`memory-qa/qa.ts:95-110`).

## 4. The five changes that would most improve the plan

1. **Freeze what the reader actually sees.** Define product-returned evidence, opaque IDs, ranked provenance and exact token packing before writing adapters. This prevents the largest fairness and leakage failures at their shared boundary.
2. **Turn the systems table into executable capability records.** Prove each pinned engine/wrapper pair, all model roles, readiness, isolation and local deployment. Keep agent-runtime's native runtime distinct and retire the unverified OpenMemory assumption.
3. **Reserve and protect a real confirmation experiment.** Name the corpus and custody allocation, freeze all configurations before any opening, and keep the public dev run from consuming sealed LoCoMo/BEAM conversations.
4. **Replace the $900 guess with a measured run matrix under the existing cap.** Measure LME and BEAM ingestion, Cat 40 slot construction and representative frontier reader calls; route every paid call through enforceable allowances. Publish the affordable preregistered matrix, not whichever rows finish first.
5. **Make the report support a purchasing decision rather than a leaderboard.** Lead with task-specific quality, ingest cost, query cost, latency and supported trust contracts. Keep ceiling ties, managed-versus-OSS differences, unmeasurable provenance and failures beside the numbers. The additional controls and categories in decisions 15-18 remain scope proposals only.

## 6. Strategy review coverage and release conditions

**Premise and scope.** The useful outcome is a reproducible answer to “which of these six OSS systems fits my workload and operating budget?” The do-nothing cost is continued comparison of unmatched published scores. The best near-term architecture is the existing corpus/scoring machinery plus inspectable product adapters, not a new benchmark platform. No system/category additions or removals were auto-applied.

```text
Existing corpora and scorers
  -> sanitizer: opaque identities, dated content, no labels
  -> frozen adapter + product + configuration
  -> completed ingest snapshot -> public retrieval -> frozen evidence context
  -> common reader -> independent scorer -> denominator-complete report

Custodian-only corpus -> same frozen path -> aggregates only
Native agent-runtime runtime -> same tasks -> separate native-runtime table

Missing config/keys -> blocked, no paid request
Empty retrieval -> valid empty context, still in denominator
Partial ingest/async work -> not ready, no counted query
Product failure -> retained attempt + terminal service-quality outcome
Invalid harness/cap exhaustion -> invalid/partial, never a product loss
```

| Review area | Required proof before counted execution |
|---|---|
| Architecture | One evidence contract; separate native-agent lane; gbrain replay parity. |
| Errors and rescue | Explicit unavailable, unsupported, product-error, invalid-harness and budget-stop states; bounded retries with attempt history. |
| Security | Opaque-ID boundary, no answer keys in vendor calls, private custody artifacts, isolated VM/container networks and credentials, disabled unsolicited telemetry for sealed text. |
| Data flow | Completed-ingest barrier, idempotent resume, independent namespace isolation and reset after pending work drains. A late write after reset must not contaminate the next item. |
| Code quality | Reuse corpus normalization, existing scorers and ledger; inspect AMB adapters before building replacements. A Python sidecar is not automatically required for an existing HTTP/TypeScript API. |
| Tests | Keyless contract fixtures plus live small fidelity probes. Mutation cases must reject leaked gold IDs, inflated provenance, omitted failed rows, stale post-delete results and deletion of all retained facts. |
| Performance | Measured write amplification and index-ready time at LME/BEAM scale; identical VM class/concurrency for latency comparisons; cold and warm costs kept separate. |
| Observability | Immutable request/response/context receipts, identity manifests, ingestion counts, job completion, token accounting, provider usage and per-attempt failure classification. Public receipts must exclude sealed rows and secrets. |
| Rollout | Dev spike, contract tests, vendor review, committed preregistration, custodial execution, then report. Vendor silence is not endorsement; a correction after frozen evaluation starts requires an amendment and new eligible cells. |
| Long-term maintenance | Versioned adapters with capability declarations and a keyless CI contract suite. Preserve failed historical cells instead of overwriting them on a release upgrade. |
| Design/UX | SKIPPED: no UI scope. The report itself must expose partial, unsupported and invalid cells rather than hiding them in notes. |
