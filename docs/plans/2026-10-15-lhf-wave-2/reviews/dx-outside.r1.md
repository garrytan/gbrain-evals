## F1 — A remote client cannot opt out of the proposed context-pack wire break

Item 8b changes `context_pack` specifically for remote callers, but `remote` is a trust boundary, not a declaration that the consumer reads only prose. The operation has no `fields` or format parameter (`src/core/ops/facts.ts:696-705`). The existing host setting and thin-client header select full **search/query rows**, not full context packs (`src/mcp/result-rows.ts:1-13`). Thus the plan's general promise that `fields: "full"` restores everything does not protect a remote client reading `cards[i].summary`, including a remote CLI consumer. Keeping `protocol_version: 1` while deleting fields violates the additive-forever contract (`docs/protocol/MEMORY_VERBS_v1.md:26-35`). Changing `budget_used` from tokens of `text` to serialized-result tokens separately breaks its documented meaning (`:865-868`).

Keep the default v1 shape and budget semantics, and negotiate compact presentation explicitly or compact it in a client adapter. If default removal is required, it needs a versioned migration decision, not just a behavior notice. Specify the exact field allowlist rather than “duplicated prose”: `text` does not render `edges`, fact IDs/provenance, or card `page_status` (`turn-context.ts:870-875`; protocol `:880-882,904-910`). Add remote old-client conformance and local/thin-client/remote parity fixtures, plus an example of requesting each supported representation. Report serialized size under a new, separately defined field. This confirms the CEO contract objection with the concrete escape-hatch gap; accepting this recommendation changes the plan's default-presentation direction.

## F2 — The lean-row default is neither transport-complete nor machine-reconstructible

Item 8a puts the reconstruction instructions in the existing `[gbrain search]` line. `searchCountLine` returns null when `keyword_total` is absent (`src/core/search/keyword-paging.ts:247`), which includes `query` and any item-4 skip that omits the field. Even an always-present prose line is not a machine contract. `content[0]` deliberately remains a bare JSON array and later blocks carry human/model notices (`src/mcp/dispatch.ts:387-423`). A JSON consumer must not parse English to recover trust and write-safety labels. Also, `create_safety` has no single default: `createSafetyFor` maps evidence to `exists`, `probable`, or `unknown` (`src/core/search/evidence.ts:107-116`). The plan must name that mapping, not imply a constant.

Define a structured sparse-row contract alongside an unconditional model-visible defaults block, covering search, query, keyword paging, skipped counts and timeouts. Omit only values that exactly satisfy the declared rule; encode genuinely unknown/missing provenance distinctly so omission cannot promote it to `operator_curated`. Preserve non-default values inline. Require a keyless round-trip assertion that reconstruction reproduces the pre-elision safety/date fields for mixed-trust and legacy rows, and verify per-call `fields: "full"`, host-wide full rows and the thin-client override. Keep the array shape and actionable source/chunk identifiers unchanged.

## F3 — The cosine tolerance permits a different “this page exists” instruction

Item 3's `1e-6` float tolerance plus order digest does not protect downstream categorical behavior. The current evidence classifier compares the raw cosine against `0.8` and maps a passing value to `high_vector_match` / `create_safety: "exists"` (`src/core/search/evidence.ts:64-74,107-116`). That field explicitly tells the agent not to create a duplicate, rather than merely showing a diagnostic score.

I reproduced a crossing using the actual JS cosine function and PGLite's vector extension, with query `[1,0]` and chunk `[0.8,0.6]` represented as Float32 values. JS returns `0.7999999928474427`; SQL `1 - (q <=> chunk)` returns `0.800000011920929`. Their difference is only `1.9073486234866266e-8`, well inside the proposed tolerance, but the same row changes from `weak_semantic` / `unknown` to `high_vector_match` / `exists`. A one-row order digest is identical.

Gate exact evidence/create-safety equality, not just numeric proximity. Include threshold-adjacent vectors at the default and configured evidence floors, on both engines and relevant storage precisions. Preserve the old categorical decision for ambiguous numerical boundary cases, or explicitly separate any intentional behavior change from the pure-performance claim. Do not relax a passing tolerance into permission to change an agent's write advice. This is a concrete item-3 gap beyond the earlier CEO observations about the benchmark fixture.

## F4 — Date elision makes the surviving date explanation contradict the default

The model-visible date line is rendered from the already-projected rows (`src/mcp/dispatch.ts:419-421`). `dateLabelLine` interprets an absent `effective_date_source` as `unrecorded` (`src/core/search/date-labels.ts:25-40`). The probe shows that removing `effective_date_source: "date"` changes the text from “date = document date” to “no source = date of unrecorded origin.” Item 8 would therefore tell the agent both that omitted values mean document dates and that those same dates have unknown provenance.

Render this line from the pre-projection date semantics, or teach it the explicit sparse-row defaults from F2. Do not globally equate every missing source with `date`: genuinely unknown dates must remain unknown. Pin complete MCP content blocks for ordinary document dates, event dates, fallback dates and genuinely missing sources, in mixed lean and full responses.

## F5 — Requested-type probes cannot supply the promised type-repair advice

## F7 — A failed saved-fact lookup can still be announced as a clean memory miss

Item 2 specifies a LIKE fallback for CJK and a missing index, but not a failed prefilter. `matchingSavedFacts` currently catches its read errors and returns `[]` (`src/core/ops/search.ts:424-426`). No saved-fact failure is added to retrieval degradation. When page results are also empty, `buildEmptyRetrievalBlock` can consequently say “no retrieval degradation — this is a clean miss” (`src/mcp/dispatch.ts:460-477`). This is particularly misleading for an explicit correction previously saved with `remember`: an agent may conclude it was never stored.

Carry a real success/failure status through the optimized lookup. Fall back to the old semantics on a prefilter error; if both paths fail, return partial page results with a stable saved-facts degradation code and a model-visible notice, not an empty-success interpretation. The notice needs a cause category, the appropriate caller/host recovery action, a verification step and a troubleshooting link; never include raw query text or database credentials. Inject a prefilter failure and a fallback failure in keyless remote tests and assert that neither can produce a “clean miss.” This is additional to, not a substitute for, the CEO's semantic-parity blockers on FTS.

## F8 — Skipping a keyword count needs an honest public state and an honest denominator

Item 4's “only when the keyword arm needs it” does not define what the agent receives when the count is intentionally not run. The public contract currently promises a count on every search and distinguishes unknown from zero (`docs/mcp/TOOL_REFERENCE.md:401`; `keyword-paging.ts:162-167`). A hybrid shortlist is not the strict distinct-page match set, so an underfilled ranked page cannot by itself justify substituting its row count. Omitting both the count and degraded marker also lets the under-1% `keyword_count_unavailable` gate pass by not measuring the skipped calls.

Define the skip predicate and its response explicitly before implementation. Preserve exact counts wherever they can actually be proven; otherwise report a null count with a documented intentional-skip state and a model-visible explanation, retaining `match: "keyword"` and executable `next` pagination as the exhaustive route. Report count coverage over all eligible searches, including intentional omissions, separately from failures/timeouts. Update the count and timing docs to match the new scheduling, and test returned rows plus the full continuation/count contract rather than only elapsed time.
