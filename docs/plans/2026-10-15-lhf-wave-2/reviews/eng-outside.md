## F1 — Rejecting ambiguous attendance in the resolver still changes the rest of search

Item 9 promises that a phrase such as “who joined acme-example” keeps the normal retrieval path when its anchor is not a meeting/event. A guard only in `relational-recall.ts` cannot deliver that. `isRelationalQuery` independently calls the syntax parser (`src/core/search/relational-plan.ts:341-343`); `hybrid/rank.ts:125` uses that result for keyword-arm confidence, and `hybrid/request.ts:341` uses it to suppress title-mention boosting. Once the broad phrase is added to the parser, those callers continue treating the query as relational even when the guarded arm returns no rows.

The keyless probe uses the existing vocabulary-extension seam to admit `joined` as proposed, then exercises the real weight function. With two equal keyword scores, a configured confidence floor of 0.6 and a voting vector arm, normal search applies lexical weight 0.5; the syntactically relational case applies no downweight. This knob is opt-in, so the example is not a claim about every default search. It proves that “no attendance edges returned” does not establish the promised unchanged fallback.

Carry the authorized anchor-disambiguation outcome through the shared request/arm result and use it for every ranking consumer of the new ambiguous phrases. Preserve existing unambiguous relation behavior; do not use `fired` as a substitute for accepted intent, since a valid relation can have zero edges. Test rejected employment/education/location phrases against baseline scores, order and evidence with the relevant ranking knobs enabled, not just the absence of an attendance result. Include unresolved, private, multi-source and schema-pack-alias anchors. This also adds concrete ownership needs for `hybrid/request.ts`, `hybrid/rank.ts` and the shared intent contract.

## F2 — NULL/not hydrated is not the baseline representation of a zero or mismatched vector

Item 3 maps zero-norm vectors to NULL/not hydrated and removes dimension mismatches. The baseline hydration map contains both kinds of stored vectors; `cosineSimilarity` returns zero for them, and a nonempty map makes every result enter the normalized blend. Only genuinely missing maps trigger the unchanged-row early return (`src/core/search/hybrid.ts:1604,1621-1647`). My fresh baseline probe with input scores `[1.4, 0.7]` returns those scores with no cosine fields for all-missing vectors, but `[0.7, 0.35]` with `cosine: 0` when one stored zero or wrong-dimension vector exists. A healthy vector elsewhere in every fixture would hide the defect.

Represent hydration presence independently from scalar value: retain hydrated zero/mismatched rows with cosine zero while guarding operator evaluation; omit only rows the old hydration read omits. Add all-zero, all-mismatched, all-missing, mixed text/image and unified-multimodal cases on both engines. Keep the new exact `create_safety`/evidence gate. The round-1 threshold crossing is not fixed by merely specifying that gate: define the narrow fallback or equivalent computation that preserves categorical decisions and ordering near numerical boundaries, including lean-score rounding, or drop the item if it cannot meet its own contract. A blanket exception for category flips within 1e-6 would reopen the original defect.

## F5 — The new executeRaw jitOff route needs a combined latency and cancellation contract

Routing item 1 through the existing `jitOffRead` introduces a transaction, an awaited `SET LOCAL`, the query and commit (`src/core/postgres-engine.ts:376-378`; `postgres-engine/search-settings.ts:25-30`). On an already-jit-off remote database, those additional serial round trips can exceed the scan time saved by EXISTS. The audit's estimated 30–35 ms saving cannot justify roughly three extra 30 ms round trips; this is a mechanism-based regression risk, not a measured result of an implementation that does not yet exist.

There is a second seam in the same API: `executeRaw` already honors `signal`, `timeoutMs`, `deadlineAt`, pool-wait accounting and checkout gauges (`postgres-engine.ts:2879-2904`). A direct jitOff callback using `tx.unsafe` must not bypass those controls or introduce another reservation inside a transaction. `runBoundedStatement` already shows a pipelined transaction envelope and recomputes its bound after acquisition; evaluate a combined implementation rather than stacking wrappers blindly.

Gate typed hit/miss queries at jit on/off and RTT 0/30 independently of item 5, including when item 5 misses its lateness cutoff. Test pre-aborted and in-flight cancellation, combined timeout/jit options, exhausted pool waits, nested success/failure and restoration. Preserve the existing raw-query behavior when jitOff is absent. Choose the lowest-round-trip safe envelope, not a session-level setting that can leak through a transaction pooler.
