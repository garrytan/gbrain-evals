# Independent adversarial review of the eval-category wave

The wave is worth doing, but the original plan is not ready to execute as nine capability evaluations followed by automatic gate promotion. Several rows conflate a supported mechanical contract with a harder capability that gbrain does not currently provide. A suite built literally from this plan could either go green without measuring the advertised behavior or create an unbounded product-development project disguised as a bug-fix wave.

## 1. Cross-cutting problems

**“Pass cleanly, then gate” selects the exam after teaching to it.** Deterministic safety invariants can become regression gates once the harness is proven and the contract is agreed. Quality metrics need preregistered tolerances, uncertainty and a fixed baseline; they need not reach 100%, and a post-fix pass is not independent evidence of improvement. This is already the parent plan's accepted amendment 4, not a new process request. N4 correctly remains report-only despite identifying fixable bugs: some misses are documented limitations, not defects.

**Independent gold is necessary, not sufficient.** A generator ledger avoids reading answers out of gbrain, but the same author can encode the same mistaken assumption in the generator, renderer, oracle and product fix. Hold out scenario families and semantic constructions, not just seed values or names. Keep reference scoring free of product imports, independently audit a stratified label sample, and use deliberately broken product substitutes to prove each metric can fail. `eval/runner/evaluator/gold-store.ts:1–14` explicitly says its isolation is in-process; a JavaScript private field is not a filesystem sandbox or a sealed holdout.

**Presence must prove exposure, not merely storage.** Before measuring deletion, show the target was actively reachable through each tier being scored. Before measuring an abstention or a privacy refusal, show an answerable/public twin succeeds. Before claiming an arm helped, show that arm actually executed. Preserve every planned probe in accounting, including errors and unsupported cases; do not silently turn product ingestion failures into an excluded “bad fixture.” Distinguish a genuinely broken setup from the product failing the intended write path.

N6 supplies a good model, but not a complete gate policy to copy. Its report distinguishes 3,854 exposed probes from 1,546 signal-bearing ones and admits that transports are replayed in process. Its current verdict expression (`n6-visibility-fuzz.ts:753–761`) checks leaks and accounting validity, not a minimum signal-coverage floor. A broad fail-closed regression could reduce utility and still satisfy that expression if presence survives. New safety gates should require both no prohibited output and a preregistered minimum set of successful authorized reads, including the relevant tier witnesses.

**PGLite-only and stub-only are limited claims.** The parent plan's accepted amendment 8 requires a small real lifecycle across both engines, local CLI, stdio and HTTP, plus restart. N3/N4/N6 intentionally have narrower contracts. New rows should preserve that honesty rather than treating the defaults as universal evidence. Also, current gbrain includes System One hooks in CRAG, think and turn-context. “Stay out of those hooks” is an editing rule, not experimental isolation: pin the effective configuration and disable optional slots explicitly for baseline comparisons, then test intentional enabled variants separately.

## 2. Category-by-category adversarial review

### N1 — Knowledge update and supersession

**Ways to win without solving the problem.** Always return the last-ingested value; remove all older records; return both old and new with the current value first; or never update and rely on probes whose latest value is lexically easiest. “Stale served” is ambiguous: a correctly labeled historical citation is not a stale assertion. A page containing the new value can earn a hit without delivering the sentence needed to answer. Repeated probes of one chain are not independent observations.

**Capability mismatch.** gbrain has several different update mechanisms, not one universal current-state resolver. `facts/supersede-resolve.ts` resolves explicit page-local `superseded by #N` links; it does not discover natural-language changes. `facts/write-single.ts:1–20,141–173` uses an embedding-neighbor threshold of 0.95, same kind and changed text for implicit supersession, and explicitly degrades without an embedding provider. `ops/chronicle.ts:154–181` exposes ontology proposals with their own dated semantics. These do not establish that generic `search`, `recall`, `entity` and live `think` all return only the current truth. The last path is not a zero-dollar semantic test merely because a separate LongMemEval arm has a budget.

**Required amendment.** Split scores into explicit update application, implicit update discovery, and delivered-answer correctness. Reuse N3's independent valid-time/recorded-time ledger and add out-of-order arrival, A→B→A, unchanged repeats, simultaneous multi-valued facts, future-effective values and unrelated same-kind claims. Include latest-recorded and latest-valid baselines. Score current assertions, historical availability, provenance and collateral expiry separately at every read surface. Use a frozen real-embedding/live-answer arm for semantic claims; a scripted dedup result proves bookkeeping only. Cluster statistics by entity history. Keep LongMemEval-S as development/regression evidence, as the parent amendments already require.

### N2 — Contradiction surfacing

**Ways to win without solving the problem.** Judge only pairs retrieval already surfaced and omit all missed planted pairs; flag every disagreement; deduplicate many outputs into one successful pair; or let the same judge produce the labels and the predictions. Pair recall's denominator is gold conflicts; precision's denominator must be all predicted conflict pairs, not “planted pairs.” Resolution-kind accuracy is circular if the reference just copies gbrain's routing rule.

**Gold is not ready to scale blindly.** `eval/data/gold/contradictions.json` warns that claims must be checked in the corpus. More importantly, `eval/generators/amara-life.ts:232–275` labels `c-010` a contradiction while its reason says the later email reflects pilots added since the note. `c-007` describes an earlier tentative plan. These are exactly the temporal/proposal distinctions the proposed category promises not to misclassify. This is a label-review requirement, not proof that every existing pair is wrong. Holder disagreement also needs a finer contract: two subjective preferences can coexist; two holders asserting incompatible objective facts about the same time may still warrant surfacing uncertainty.

**Capability mismatch.** `eval-contradictions/runner.ts:156–215,333–375` searches first, generates cross-slug chunk pairs and intra-page chunk/Take pairs, date-filters, then invokes its judge under a cap. It is not a corpus-wide, fact-identity-aware contradiction scanner, and its LLM “judge” is the system under test. `auto-supersession.ts:1–24` produces proposals, not applied resolutions. Its current proposal taxonomy even includes a hint toward a deferred timeline-writing action (`types.ts:61–72`). Do not claim a resolved brain from a correct label or command string.

**Required amendment.** Independently label a fresh claim ledger with subject, predicate, value, units, validity interval, holder and epistemic status; validate every rendered span. Report candidate-pair recall, conditional classifier quality, and end-to-end conflict recall separately. Include both genuinely contemporaneous conflicts and delayed reports about the same event, not only differing document dates. Label acceptable resolution actions as sets where appropriate, and grade command applicability separately. Run the real production detection path plus a fixed-pair diagnostic; never substitute the diagnostic for discovery. Count capped/unjudged pairs and product-judge errors explicitly. Split by scenario family rather than cloning 150 versions of ten pairs.

### N5 — Forgetting and withdrawal residue

**Ways to win without solving the problem.** Never materialize the canaries into a tier; expire everything; search for an exact canary while its paraphrase survives; test only in-memory hot facts; or inspect a newly cleared cache rather than a previously populated one. “Residue = 0 everywhere” also penalizes the audit trail that the protocol deliberately preserves.

**Capability mismatch, the most important one in the plan.** The verb expires a fact by opaque ID and keeps its audit trail (`core/verbs.ts:343–349`). The durable ledger matches source, visibility, subject and normalized claim fingerprints (`facts/withdrawal-schema.ts:1–74`): case, spacing and punctuation variants are covered, arbitrary semantic paraphrases are not. `facts/forget.ts:1–10` explicitly says original prose, files and backups may retain text and Markdown-only copies do not carry DB-only withdrawals. This is not physical erasure or universal semantic lineage retraction. A stubbed dream can plant predetermined descendants, but cannot prove that live synthesis propagates and removes every equivalent assertion.

**Required amendment.** Define a surface/authority matrix: active fact recall, searchable authoritative derived content, raw source text, history, export and backup have different retention contracts. Scope zero residue to prohibited active outputs, and report historical retention honestly. Establish before-forget witnesses for every target×tier, with a retained public twin and semantically near retained claims. Test same text on another entity, another source and another visibility; subjectless and legacy wildcard withdrawals; restart/reindex/reimport; concurrent stale write; managed/unmanaged writes; and unauthorized forget attempts. Separate exact normalized reactivation from semantic paraphrase resurrection. The latter is a report-only capability gap unless a separately approved provenance/retraction design is built. Explicitly document reinstatement behavior rather than inventing a restore API. Extend the existing lifecycle observer/drivers instead of creating a disconnected canary-only world.

### A4 — Abstention

**Ways to win without solving the problem.** Always abstain, emit hedged guesses that a judge counts as abstentions, make negatives obviously out of domain, or tune the threshold on the test set. A balanced sample is useful for diagnostics, but its abstain precision is not deployment precision at a different unanswerable-question prevalence.

**Capability mismatch.** `search/crag.ts:5–30,67–106` grades retrieval strength and optionally escalates; it does not decide whether a requested attribute is present or issue an “I don't know” answer. An exact entity lookup is immediately strong even when the page omits the asked-for attribute. Current `think/decide.ts:1–18,100–132` has a distinct optional S4 answerability path, with coverage/evidence safeguards and fail-open behavior. The plan must name which answerer it tests: a harness reader, ordinary think, and S4-enabled think are different systems.

**Required amendment.** Report gate calibration against evidence sufficiency and actual answer abstention against answerability as separate tasks. For ordinary CRAG, show its coarse operating points rather than implying a continuous calibrated probability curve. Add hard negatives with the right entity/wrong attribute, multi-hop missing support, time/source/permission restrictions, contradictions, and an answer not retrieved despite existing in the authorized corpus. An oracle-evidence reader control separates retrieval failure from answerer failure. Report coverage, wrong answers per attempted answer, unanswerable-answer rate, answerable false refusal and correct useful answer rate, with null rather than perfect risk at zero coverage. Freeze thresholds on development data and keep safety refusals separate from epistemic abstention.

### N7 — Open loops and commitments

**Ways to win without solving the problem.** Plant only question marks after exactly the detector's grace window; treat any response as fulfillment; give null due dates to almost every example; or define ranking gold using the same due-date/backlink formula that `waiting` uses. Aggregate closure accuracy can conceal a model that calls every item still open when closures are rare.

**Capability mismatch.** `google/loop-detect.ts:1–26,112–164` is a Gmail thread-turn state machine: inbound/outbound grace windows, noise exclusions and turn-flip closure. It is not a Slack/calendar commitment detector. `google/loops-extract.ts:1–25,147–159` is a separate email-thread LLM extractor for unresolved commitments and decisions. Its persistence loop upserts extracted commitments (`:402–456`); omission of a previously extracted commitment is not a reconciliation operation that marks that stored loop fulfilled. `loops/loops-store.ts:186–201,238–255` supplies thread closure and commitment staleness, while `ops/loops.ts` supplies manual close. A later “thanks” can end reply waiting without fulfilling a promise.

**Required amendment.** Separate unanswered correspondence, extracted commitment identity/fields, fulfillment state, and ranked counterparty groups. Start with real Gmail-shaped metadata and sync/extraction entrypoints; label Slack/calendar as unsupported/transfer cases unless an adapter is explicitly added. Freeze the clock and include nudges, partial replies, forwarding, several counterparties, calendar notices, acknowledgments without delivery, fulfillment followed by a new promise, mute/manual-close replay and stale source refusal. Score dates conditional on genuinely specified dates plus null accuracy; state timezone/date precision. Rank gold should be independently assigned user priorities, or publish a conformance check rather than claiming ranking quality. Group-level nDCG must match the counterparty grouping `waiting` actually returns.

### N8 — Proactive recall

**Ways to win without solving the problem.** Put an explicit memory question into every “trigger turn,” inject everything, score a fetched page rather than the delivered block, or call a useful related memory a false alarm merely because it cannot answer a narrow question. Clearing session state between every turn can hide duplicate spam and stale context.

**Gold/controls are not yet independent enough.** `associative-recall-v1/README.md` says independent human relevance review is still required, names three disputed negatives, and explicitly warns that an unavailable answer does not make related memory irrelevant. Its 480 probes include indirect questions, direct controls and negatives across 120 families; they are not 480 independently labeled unsolicited triggers. Its public “holdout” is not a new sealed confirmation set. Cat34's wrapper uses gbrain's own fixture/gold/scorer and distinguishes production and simulated contract harnesses (`cat34-brainbench-memory.ts:1–37`). Merging the scores does not improve their independence.

**Capability mismatch.** `context/volunteer.ts:1–24` is a deterministic precision-biased entity-pointer mechanism. `context/turn-context.ts:1–23,291–319` assembles pointers, volunteered pages and world-visible hot facts under deduplication and a byte budget. That is valuable, but not equivalent to general associative recall, prospective action execution or agent use of the injected memory. Current turn-context also contains an optional System One S6 stage; record whether it acted.

**Required amendment.** Keep a shared family ledger but distinct proactive-trigger, relevance/association, delivery-conformance and downstream-use scores. Get the existing relevance labels adjudicated before publication. Add independently authored conversational turns that never ask for recall, matched innocuous turns, legitimate useful associations without complete answers, compaction/restart, delayed delivery, per-session suppression and grants. Score the final injected bytes/spans, not the pre-budget candidate pool. Report recall at a fixed false-alarm budget, useful precision, redundant injections per session, tokens and delivery p95. Compare never-inject, always-inject and simple turn-text retrieval. A small real hook/IPC trace is needed to claim harness delivery; contract replay alone is not native activation evidence.

### N9 — Multi-hop with held-out wording

**Ways to win without solving the problem.** Retrieve one page that already contains the answer and call it multi-hop; encode the graph path in the question or slug; label every connected page relevant; increase k until all support fits; or author a new “held-out” grammar after examining the product parser. A same-index on/off comparison isolates the relational arm, not all graph influence.

**Capability mismatch.** `search/relational-intent.ts:1–25,33–46` maps regex archetypes to one/two seeds, one relation-type set and a direction. `relational-recall.ts:294–337` passes those constraints to fanout or intersects two fanouts. This is not an arbitrary sequence of differently typed joins, quantifiers or negations. It can fail a compositional question before traversal begins. Importing HotpotQA passages also does not magically populate the typed graph needed by the treatment.

**Required amendment.** Extend `relational-ab.ts`, which already has shared index/vectors, treatment telemetry, cost accounting, frozen paraphrases and paired results, rather than adding a parallel version of the same experiment. Add a new graph-structure split and independently authored wording together. Specify required supporting spans/edges and answer identity, then use bridge deletion, relation reversal, graph rewiring, wrong-source twins and shortcut removal to test actual composition. Report parse success, seed resolution, graph coverage, arm firing and final all-support delivery separately; failures remain in the end-to-end denominator. Match k and delivered token budgets, reranker and expansion settings. Defer external QA until the small graph challenge can distinguish template success from generalization.

### N12 — Ingestion format fidelity

**Ways to win without solving the problem.** Render only the parser's own positive fixtures; preserve turn count while swapping speakers; split and merge different turns so count errors cancel; or demand timestamps the input never contained. Scoring only parsed pages rewards dropping the difficult ones.

**Capability mismatch.** `transcripts/detect.ts:75–88` registers seven adapters: Hermes, OpenClaw, Codex, Claude Code, Grok, Claude export and ChatGPT. The plan omits Hermes and OpenClaw and lists “generic JSON,” which is not a generic adapter in this registry. `transcripts/types.ts:17–21,36–43` defines source timestamps and user/assistant roles, not universal meeting-speaker/attendance semantics. The separate conversation parser supports regex/polish/fallback/no-match, possible epoch/default timestamps, timezone warnings and date fallback diagnostics (`conversation-parser/types.ts:37–103`). Attendance is another extraction stage, e.g. `link-extraction.ts:660–685`, not a field guaranteed by parsing.

**Required amendment.** Enumerate the actual format/entrypoint/version matrix and test import→stored page→downstream parser as well as each parser seam. Keep deterministic source-spec fixtures plus independently captured/sanitized export-shape fixtures; product fixtures are regression evidence, not independent format evidence. Score aligned turn identity, order, speaker/role, preserved text and timestamp semantics; test wrong attribution explicitly, not just count. Distinguish exact UTC instant, date-only/local precision, inferred time and absent time. Include ChatGPT branch/regeneration paths, duplicate messages, tool-only traffic, code fences, multiline text, missing timestamps, malformed/truncated exports and honest zero-session diagnostics. Move attendance scoring to a separately named extraction subscore with present-versus-mentioned gold. Stubbed fallback proves plumbing; live fallback quality needs its own paid row.

### N13 — Code intelligence

**Ways to win without solving the problem.** Sample only distinctive symbols, report blast recall without precision, count any chunk containing a reference as a correct symbol reference, or use the same indexer to construct both product edges and reference edges. nDCG can be inflated if the “natural-language” queries are just exact symbol names. The table promises `code_callees` and `code_flow`, but its listed metrics do not independently cover either.

**Capability mismatch.** Current `ops/code-intel.ts:288–307` explicitly suspends all six code read operations for remote agents; trusted local callers remain supported. `commands/code-refs.ts:1–18,39–75` does substring search over chunks, not semantic reference resolution. `chunkers/symbol-resolver.ts:1–24` is a bounded within-file resolver with ambiguity/unmatched cases. `code-intel/recursive-walk.ts:150–230` performs BFS over those stored edges, not control-flow or runtime execution analysis. `code_flow`'s sinks are static classifications. A SCIP definition/reference index alone does not supply independently verified caller graphs, dynamic dispatch or execution-flow gold.

**Required amendment.** Defer the broad two-OSS-repository quality project from this wave, but keep a cheap capability/readiness inventory and small curated semantic microcorpus. If expanded, pin repositories, compiler configuration, generated files and indexer versions; independently verify a stratified gold sample. Define identity as file/range/symbol, normalize chunk outputs without awarding unlimited credit, and separate lexical chunk refs from semantic refs. Include aliases, imports, overloads, inheritance, callbacks, same-name methods, recursion, dynamic calls, deleted/moved files and stale indexes. Score blast precision as well as recall, callees separately, flow edge/path and sink correctness, ambiguity, readiness and truncation honesty. Use LSP call-hierarchy/appropriate compiler analysis plus adjudication where available, not an unspecified “deterministic index.” Local operation correctness and remote safety refusal are separate results; do not imply agent-facing availability from a local pass.

## 3. Ordering and scope

Keep one integrated evals PR and one integrated gbrain fix-wave PR. The problem is not PR count; it is starting nine different measurement projects before their semantics are settled.

1. **Freeze the experiment before five implementation lanes diverge.** Pin exact product/evals revisions, configuration, operation entrypoints, unit of scoring, planned counts, baselines, coverage witnesses and unsupported behavior. Prove the evaluator on perfect, empty, stale-only, wrong-source and deliberately corrupt outputs. Resolve N2 and N8 label problems first.
2. **First executable slice: N5 + N1 in the existing lifecycle matrix, alongside a narrow N12 format slice.** Reuse N3 state ledgers and N6 public-twin/ghost ideas. Include PGLite and Postgres with one real stdio/HTTP restart path for critical safety cases. Run before/after on explicit withdrawal/update semantics first. This is a bounded extension, not a demand for the entire Cartesian product.
3. **Then N2 and A4.** These expose semantic quality and answer safety, but require distinct product-judge and reference-judge roles and small live pilots. Keep natural-language update/paraphrase withdrawal failures visible as limitations unless implementation scope is deliberately approved.
4. **Then N7 and N8.** Both need stateful temporal/session scenarios and independent labels, not just more rows. Split mechanical supported-contract tests from aspirational semantic outcomes.
5. **N9 is an extension of relational-ab; defer the external arms. N13 gets a scout, not the full project.** Retain its category ID as planned/report-only if useful, but do not count a scaffold or a readiness check as delivered code-intelligence quality coverage.

Cut the promise that all nine categories must pass, the implication that all identified weaknesses are bugs, and the default automatic gate flip. Add a small live semantic check to the mostly stubbed write-path work: otherwise the wave tests where perfect facts go while still not measuring whether correct facts are produced. Add latency/token/error accounting at the existing seams rather than building a new dashboard system.

The category prices are guesses, not spending guarantees. The $150 cap needs the existing shared reservation ledger across concurrent lanes, retries, embeddings, extraction, synthesis and evaluator calls. Quote cold-cache cost from a measured pilot; a query-only estimate omits the expensive write path. Do not represent `$0` stubbed execution as semantic evidence simply to stay inside the estimate.

## 4. A bug-to-fix loop that does not train on the exam

```text
freeze contract + reference scorer + development corpus
                         |
old pinned product -> raw observations -> independent scoring
                         |
classify: product bug / feature gap / oracle error / harness error
                         |
minimal failing regression -> mechanism-level product fix
                         |
same development corpus + orthogonal regressions + untouched families
                         |
fixed release candidate -> one preregistered sealed confirmation
                         |
publish all deltas, failures and limits; promote eligible regression gates
```

**Triage before patching.** Every finding records the promised contract, affected callers/engines, minimal input, expected behavior derived independently, actual response and precise version. Wrong source or silent reactivation is a bug; missing arbitrary semantic paraphrase retraction is a feature gap. A mislabeled temporal change is an oracle error. Do not “fix” the product to reproduce a wrong oracle.

**Fix mechanisms, not generated phrases.** Use development failures to construct small product tests, then require orthogonal variations: alternate names and formats, different valid/recorded ordering, other sources/engines, nearby retained claims, and changed graph topology. Prohibit category IDs, fixture filenames, canary prefixes and gold-specific conditionals in product logic. Test metamorphic properties such as source renaming, reordered independent writes, idempotent replay and equivalent punctuation without importing the benchmark scorer into the product.

**Keep treatment isolation.** Run baseline and candidate with the same evaluator, corpus, cached inputs where semantically valid, resource caps and config. Preserve both receipts. A scorer repair requires rescoring both arms and a labeled erratum, never overwriting the old result. A new feature contract gets a new versioned evaluation, not a retroactive change that makes the failing baseline look better or worse.

**Preserve a real confirmation boundary.** Fresh names/seeds in a known grammar are robustness checks, not independent confirmation. Hold out histories, scenarios and constructions from fix authors; release the final candidate before opening labels. Freeze selection/stopping rules and count every access. If confirmation inspires another fix, that set is now development data; do not keep rerunning it as “held out.” A small sealed set beats nine large exposed sets for transfer evidence.

**Separate correctness and inference.** Fail exact safety violations immediately. For quality, use paired clustered uncertainty at the natural unit (history, pair family, email thread, conversation session, graph world, or repository/module), preregister the comparison family and multiplicity treatment, and give the absolute effect size beside significance. Reruns of one world and hundreds of probes on one entity do not create hundreds of independent samples. For important missing outcomes, show pessimistic/optimistic bounds and coverage instead of silently deleting them under an error allowance.

**Gate promotion is a reviewed decision.** Require immutable reference checks, nonvacuous exposure witnesses, a fixed regression corpus, stable reruns and documented runtime. Safety gates enforce exact contracts plus authorized-utility floors. Noisy quality gates use agreed non-inferiority bounds; exploratory metrics stay report-only. A result fixed on its own development corpus proves the regression is repaired, not that gbrain has generally mastered the category.

## 5. Top ten amendments, ranked

1. **Replace automatic “passes after fixes → gate” with explicit safety, quality and exploratory promotion rules.** Freeze them before coding; never let the candidate set its own acceptance threshold.
2. **Rewrite N5 around the actual withdrawal contract.** Zero prohibited active output is required; semantic paraphrase retraction and physical-history erasure are not implemented guarantees. Add per-tier pre-withdrawal witnesses and retained-neighbor controls.
3. **Add a one-page capability/entrypoint matrix at the exact tested commit.** Distinguish explicit supersession from implicit discovery, CRAG from answerability, replies from fulfillment, local code reads from remote availability, and parser fidelity from attendance extraction.
4. **Make independent label and scorer validation a build prerequisite.** Adjudicate existing N2 temporal labels and N8 disputed negatives; mutation-test empty/always-positive/always-refuse/stale/wrong-source systems and protect a genuinely fresh confirmation set.
5. **Implement N1/N5 through the existing lifecycle harness before broadening.** Carry N3 temporal semantics and N6 exposure controls into a bounded PGLite/Postgres, actual-transport, restart/reimport/concurrent-write slice.
6. **Give N2 separate candidate-discovery, classifier and resolution scores.** The production contradiction judge is the treatment, not the oracle; score against independent spans and keep missed/capped pairs in the end-to-end outcome.
7. **Define A4's answerer and calibrate to useful answers, not strong retrieval.** Include exact-entity/missing-attribute negatives, a matched oracle-evidence control, false-refusal cost and distinct S4-on/off reporting.
8. **Split N7 and N8 into supported stateful mechanics and separately labeled semantic tasks.** Do not map Gmail reply closure onto promise fulfillment or associative QA onto unsolicited recall; measure final delivery and session behavior.
9. **Reuse rather than multiply harnesses, and defer N13's broad quality study.** Extend relational-ab for N9, enumerate N12 from the real adapter registry, and keep only N13's capability/readiness scout until independent call/flow gold is defined.
10. **Replace “fix every weakness” with a contract-based triage and transfer protocol.** Minimal repros and broad mechanism fixes belong in the fix-wave PR; feature gaps remain explicit. Preserve all before/after receipts, use clustered comparisons and an untouched confirmation decision, and enforce the $150 cap across write-side work and retries.

## Bounded code probes performed

At gbrain `3a284aea26889b77c633aebb4149c3016d834ee6`, imported pure modules with `bun -e` without initializing a brain:

1. `gradeRetrievalConfidence([{exact_lookup: 'title', evidence: 'exact_title_match'}])` returned `{level:'strong', reason:'exact_lookup', top_evidence:'exact_title_match'}`. This demonstrates the grading helper does not require answer-bearing text; it is not an end-to-end answerability failure measurement.
2. `normalizeLoweredClaim('prefers email.')` and `normalizeLoweredClaim('prefers email!')` both returned `prefers email`; `normalizeLoweredClaim('email is the preferred contact method')` returned different text. Together with the fingerprint equality in the withdrawal SQL, this confirms lexical normalization, not semantic equivalence.
3. `parseRelationalQuery('Who works at Acme?')` returned a `works_at` query seeded by `Acme`. `Which people work for companies backed by Fund Example?` returned a `works_at` query whose seed was the entire phrase `companies backed by Fund Example`. `Which employers have staff who advise Acme?` parsed only the `advises` relation to `Acme`. The parser does not emit a composed multi-relation query plan for these examples; graph resolution/retrieval was not executed.

The review is complete with concerns. The existing N3/N4/N6 reports substantiate the claimed seven discovered bugs (four temporal, two entity-resolution, one visibility); they do not establish that nine further category scores will be independent or that all nine capabilities already exist. No durable user-preference learning arose from this read-only review.
