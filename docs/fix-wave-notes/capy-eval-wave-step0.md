# Eval-category wave, step 0 (branch `capy/eval-wave-step0`)

Step 0 of the [eval-category wave plan](../plans/2026-10-01-eval-category-wave/README.md): the sequential groundwork the five category lanes build on. No category runner is added here. VERSION and CHANGELOG are untouched; the integrator writes one 0.10.5 entry for the wave.

## What changed

1. **Re-pin.** gbrain is pinned to master `3a284aea26889b77c633aebb4149c3016d834ee6` (v0.60.26.0, System One #5797), up from `6c8373c` (v0.60.13.0). `bun.lock` regenerated. Typecheck was clean on the new pin. The only test the re-pin broke was the documentation pin-claim check (audit B1): README, `docs/settings.md` and `docs/comparison-systems.md` now name `3a284ae`. `MODE_BUNDLES` in `src/core/search/mode.ts` is byte-identical at `6c8373c` and `3a284ae` (compared the frozen object literal) and `src/core/ai/defaults.ts` is unchanged, so the settings recommendations still describe the installed modes. README notes the new System One slots stay off without a TypeSafe key.
2. **Shared hermetic environment** (`eval/runner/hermetic-env.ts`). Strips every provider credential and endpoint gbrain reads at the pin (an explicit list from a grep of `src/` for `*_API_KEY`, `*_TOKEN` and `*_BASE_URL`, plus a pattern for key names added later), both TypeSafe names (`TYPESAFE_API_KEY`, `JEV_TYPESAFE_API_KEY`) and the `GBRAIN_DECIDE_SLOTS` eval override; points `GBRAIN_HOME` at a fresh temp directory; restores everything (removing keys set during the run) and deletes the temp home on return or throw. `withHermeticEnv` asserts System One's three preconditions are absent before and after the run (no TypeSafe key, no `GBRAIN_DECIDE_SLOTS`, no `.gbrain/config.json` or `.env` in the hermetic home), so System One is off by construction: in gbrain a slot turns on only through a TypeSafe key (`readDecideConfig` key defaults, `src/core/ai/decide/config.ts:182`), an explicit `decide.*` config value, or the opted-in eval override. A violation throws `SystemOneOnError` with problem, cause and fix wording. N3, N4 and N6 now run through it and record `resolved_config.decide: "off (no key, fresh GBRAIN_HOME)"`. N3 previously did not isolate `GBRAIN_HOME`, and no runner stripped the TypeSafe keys.
3. **Capability and entrypoint matrix** at the pinned commit: [docs/benchmarks/2026-10-01-capability-matrix.md](../benchmarks/2026-10-01-capability-matrix.md), with probe scripts P4 to P11 committed beside it. Drafted by a read-only subtask; I spot-checked its refs (`src/mcp/server.ts:318-322`, `src/core/ops/insights.ts:197-200`, `src/cli.ts:1515`, `src/core/ops/code-intel.ts:293-300`, `src/core/transcripts/detect.ts:76-86`) and reran P5, P7, P8 and P9 from the committed scripts with identical output.
4. **Promotion rules** (amendment 1). `eval/registry.ts` gains `PromotionRules` (`preregistered`, `basis`, `safety_contracts`, `quality_thresholds`, `exploratory`); every dispatched entry carries them, and an entry is `gate` exactly when it has a gating rule (tested). Each rule compares a receipt path with a frozen value. `eval/runner/promotion.ts` evaluates them; `all.ts` gates only on them. Pre-wave gating categories carry their frozen runner verdict as their one quality threshold (`RUNNER_VERDICT`), so their behavior is unchanged; wave categories may not use it (tested). `all.ts` gained `--only <ids-or-aliases>` (unknown names fail and list the valid ids) and a paid guard: any selection with a K or P category refuses without `--paid --budget-run-id <id>` naming an open budget-ledger run, and passes the id to children as `BRAINBENCH_BUDGET_RUN_ID`. `eval/runner/paid-arm.ts` is the same guard for runner paid arms; `budget-ledger.ts` gained a read-only `ledgerStatus`.
5. **Scorer mutation kit** (`eval/runner/mutation-kit.ts`, amendment 4): empty, always-positive, always-refuse, stale and wrong-source fake systems over a category-supplied answer space, and `assertScorerRejectsFakeSystems`, which requires the honest system to pass, every applicable fake to fail, every fake to change at least one answer, and a reason for any fake declared not applicable. `test/eval/scorer-mutation.test.ts` wires it into N3 (runner `summarize` + `n3Verdict`), N4 and N6 (each graded by its preregistered promotion rules, so the CI gate itself is shown to reject the fakes).
6. **Docs.** "Add a category" checklist in `eval/CONTRIBUTING.md` (pointer in `CLAUDE.md`); the plan and outside review copied to `docs/plans/2026-10-01-eval-category-wave/` with machine paths replaced by placeholders; a docs index row.

Also built, because it is a step-0 shared piece in plan section 8 that every lane needs: `eval/runner/bug-ledger.ts` (validated entries classified `bug` / `feature-gap` / `category-defect`, upsert by id, Markdown view; ledger path `docs/benchmarks/2026-10-01-wave-bugs.json`, created by the first lane that finds something). The overlay mismatch error in `gbrain-under-test.ts` now names problem, cause and fix instead of dumping JSON.

## Decision to review: N4 now gates

Under amendment 1, safety contracts gate immediately. N4's rules are five safety contracts (zero identity-group leaks, zero wrong merges on resolver, recall, remember and resolve-on-save) and two utility floors as quality thresholds (exact-lookup floor and search exact floor at 100%, so a refuse-everything system fails). All seven held at `6c8373c` (the 2026-09-30 receipts) and at `3a284ae`. Its runner verdict stays `fail` because recall of variants gbrain does not read by design keeps B-cubed F1 under 0.9; that is exploratory now and no longer the gate. N6 gained a coverage floor (`content_reachable_coverage >= 1`, which held at both commits) beside its zero-leak contracts. Reverting either is one registry edit.
