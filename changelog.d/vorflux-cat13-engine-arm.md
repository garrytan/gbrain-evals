- cat13 can now run its gbrain arm on PGLite, Postgres or gbrain's Rust store engine: set `GBRAIN_EVAL_ENGINE=pglite|postgres|rust`. Postgres needs `--pg-url` or `LIFECYCLE_PG_URL`. Before any paid request, the run refuses with exit 69 and a skipped receipt when Postgres has no URL or cannot make a scratch database, or when the Rust engine is missing from the build or its addon does not load. A Rust engine that loads but refuses a later step still fails the run as before. `--embed-cache <sqlite>` lets every engine search the same cached vectors, and each per-query row now records `latency_ms`. Without `GBRAIN_EVAL_ENGINE` the arm keeps its in-memory PGLite brain. The Rust engine's init step now receives `GBRAIN_RUST_ENGINE_ADDON`, so a locally built addon loads. First baseline: [docs/benchmarks/2026-11-18-engine-baseline/README.md](docs/benchmarks/2026-11-18-engine-baseline/README.md) (PGLite and Postgres return the same top 5 on all 548 probes; the Rust engine cannot run the bench yet because its `upsertChunks` refuses the `embeddingColumn` option that gbrain's import passes).

cat13 gains `--warm-passes N` (0 to 10): after the scored pass, the same probes run again on the same brain, timed but not scored, so a receipt can report first-pass and repeat-pass latency apart. Second build of the engine baseline (gbrain dbc85b2d): the Rust engine now imports with embeddings, but has no vector search yet, so its runs are invalid; PGLite and Postgres controls match the first build's top 5 on every probe.
