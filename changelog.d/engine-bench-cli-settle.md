- **Engine-bench's surface parity no longer times out on a CLI put_page.** On gbrain's current builds, a new page that qualifies for automatic facts extraction, written through `gbrain call put_page`, exits with a facts-backstop effect queued, as it does with its embedding effect: a one-shot gbrain command leaves both to the next process that writes, so no read in between can see them settle. The CLI wait in `eval/runner/engine-bench/surface-parity.ts` now treats facts-backstop like embedding, waiting for the write itself and its links, and still records the effect's state in the receipt. Before this, the stage's one CLI write that makes a new page reported a 30 second settle error on PGLite and Postgres. The MCP wait is unchanged, because `gbrain serve` dispatches the effect at once.
