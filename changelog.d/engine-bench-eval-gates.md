- **Engine-bench writes eval-gates.json.** A new command, `bun eval/runner/engine-bench/eval-gates.ts`, turns one wave's stage receipts into the file gbrain's Rust engine plan asks for: gates E1, E2 and E3, each with the plan's threshold as written, a PASS, FAIL or NOT_RUN verdict, what was measured, one row per benchmark and the rows that lost, plus the paired speed comparison (swap readiness criterion 8), which is reported and never a gate. E1's LongMemEval-S rows come from stage 3's equal-or-better rule at N = 470; the benchmarks engine-bench does not run are NOT_RUN with that reason. A FINAL file needs a gbrain release tag, counted receipts that agree on one gbrain commit and one Rust addon digest, and goes once to `eval/results/engine-bench/eval-gates/<tag>/<evals commit>.json`; a release-candidate or branch build gives a PROVISIONAL file, which never goes under `eval/results`. The speed stage's receipt now records the Rust addon's digest like the other stages.
