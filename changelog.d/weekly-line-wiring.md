- **Weekly held-out line: the runner plans each week from the weekly cell set, and six checks owed by the runner and cell-set reviews.** `eval/runner/weekly-line/runner.ts` now builds each week's cells with `generateWeeklyLineCells` and `weeklyLineRereadPlans` from the week, its worlds and the frozen gbrain build, keeps those definitions beside the run, and launches only after `requireWeeklyLineLaunch` passes on them; planning and launch still start nothing and call no provider. Settle now refuses a spend list with a repeated entry, an entry outside the week or a value that is not a finite number of at least 0, and records the SHA-256 of every answer and judgment file it settles; the aggregates refuse a run whose files changed after it settled. Every record a weekly cell writes carries the run id and week it ran under, and the aggregates refuse records another run wrote. The standalone `aggregates.ts block` command refuses any week without its settled marker before it computes anything. The launch check refuses an arm at another mode or reading budget than its row, any model a cell can call that the code's list and the registry entry don't both name (the extract-first server's `text-embedding-3-large` embedder is now listed, so the check refuses until the registry adds it), and server lockfiles other than the patched locks of [gbrain-evals#594](https://github.com/garrytan/gbrain-evals/pull/594). The grep agent's cell is timed from the week's answer count, so a full week's machine limit is 61 hours instead of 4. Keyless tests in `test/eval/weekly-line-runner.test.ts`, `test/eval/weekly-line.test.ts` and `test/eval/weekly-line-cells.test.ts` cover each change.
