- **A free check of what happens when several writers use one brain at once.** `bun eval/runner/multi-writer-behavior.ts` runs seven scenarios with writers in separate processes and in one process, on PGLite, Postgres or Rust (picked with `GBRAIN_EVAL_ENGINE`, as the other behavior checks do): concurrent writes to one page, concurrent creates of one slug, links and backlinks, timeline order and times (also across a Rust store-owner takeover), deletion, facts after forget or delete, and access rules for remote callers through `gbrain serve --http`. Each check reports pass, fail (wrong data), not_supported (the engine refused by name) or invalid. On Rust, a run with `GBRAIN_RUST_MULTIUSER=1` counts only when the running store proves multi-user mode is on. `matrix --gbrain-clone <path> --ref <branch|sha>` tests any gbrain branch or commit, builds its Rust addon from the same commit, and compares Rust with the switch unset against a baseline build byte for byte. Put latency p50/p95 is reported, never judged. No model or embedding calls.
