- **Weekly held-out line: a weekly runner, and four fixes to the block file.** `eval/runner/weekly-line/runner.ts` plans and records one week of the line in custody and never calls a provider. It names a week by its Tuesday launch, sets the world end to the Sunday before, and refuses once its clock is more than 14 days past that world end. It reads the week's 8 Set W worlds in slot order from that month's batch, refuses while a batch is still minting, and fills the first week a short final batch cannot reach with the previous batch's two spares. It records gbrain's highest release tag with its commit and keeps that build for the week even when a newer release lands. It orders the work as the extract-first server's cells first, then gbrain's, the memory-bank server's and the grep agent's, then particle-1's re-reads, then judging, then the aggregates. It hands the launch path that order only once a paid window is granted. It writes a settled marker only when every cell, re-read and judgment is done or recorded as a harness failure. The cell set plugs in at one wiring point and is not wired yet, so a week with a point cannot be planned until it is. Each week's run gets an identity file, and the aggregates writer now scores exactly that run, refusing records of another run or week. The block file changes in four ways. A block ends only when all four weeks carry their settled markers. Until the end it publishes no simultaneous interval and no wild bootstrap. An ended block file is never replaced by an open one. The regression flag shows a false-alarm rate only beside BG1-C's custody receipt for the pool, matched by SHA-256, and reads "unavailable" without one. The runner refuses to write a counted block file through a block writer that lacks the second and third of these. Keyless tests in `test/eval/weekly-line.test.ts` and `test/eval/weekly-line-runner.test.ts` cover each change.
